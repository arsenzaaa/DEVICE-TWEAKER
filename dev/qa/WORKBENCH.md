# Стенд разработки

Стенд позволяет воспроизвести проблему, увидеть GUI, проверить изменение и сохранить доказательства. Настройки компьютера остаются без изменений. Окна работают на отдельном невидимом рабочем столе; ввод отправляется только собственным контролам.

## Короткий цикл

Из корня репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Invoke-DevSession.ps1
```

Команда сохраняет копию входных файлов, собирает разработческую версию и запускает `Scenarios/device-flow.json`. Путь результата выводится в конце: `local/dev-sessions/dev_*`.

Для своей задачи создайте JSON по образцу [device-flow.json](Scenarios/device-flow.json) или [control-states.json](Scenarios/control-states.json). После изменения повторите тот же сценарий с предыдущим успешным запуском:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Invoke-DevSession.ps1 -Scenario .\dev\qa\Scenarios\control-states.json -CompareWith 'local/dev-sessions/папка-предыдущего-запуска'
```

Если воспроизведение сначала даёт FAIL, сохраните его снимки и исключения. Для автоматического сравнения нужны два успешных запуска с одинаковым сценарием и средой.

## Что смотреть

- `index.html`: снимки, дерево контролов, шаги и проигрыватель кадров перехода. Страница локальная, внешних ресурсов нет.
- `comparison/index.html`: до / после / разница. JSON содержит изменившуюся область и число отличающихся пикселей.
- `trees/*.json`: подписи, исходные строки, видимость, доступность, фокус, границы, флажки и выбранные значения.
- `timelines/`: кадры, контактные листы, фактические интервалы съёмки. Это частота снимков, а не FPS дисплея.
- `state/`: виртуальные устройства, настройки тестового хранилища, полные исключения с местом возникновения.
- `session.json`, `execution.json`, `process-*.json`: шаги, хеши, нормальное завершение процесса и неизменяемый read-only.
- `inputs.json`, `input/repo`, `isolation/desktop.json`: исходники и подтверждение скрытого рабочего стола.

`REVIEW_REQUIRED` появляется после первого запуска или изменения снимков. Их нужно просмотреть. `MATCH` означает совпадение контрольных снимков, но не одобрение дизайна. Эталон не перезаписывается, маски и допуски автоматически не добавляются. Несовместимый сценарий / среда, пропущенный шаг, изменённый PNG / JSON и crash report останавливают проверку.

## Фиксация просмотра

Сначала открыть PNG, разницу и кадры переходов. Затем создать шаблон:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Review-DevSession.ps1 -RunDirectory 'local/dev-sessions/папка-запуска' -CreateTemplate
```

В `review-input.json` заполнить автора, итог и каждое изображение: `ok`, `intentional-change` либо `defect`, с конкретным пояснением. `PENDING`, пропущенные кадры и несовпадение хеша не принимаются.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Review-DevSession.ps1 -RunDirectory 'local/dev-sessions/папка-запуска'
```

Результат сохраняется как `REVIEWED` или `REJECTED`. Запись сохраняет результат просмотра и привязана к точным кадрам. Проверка хешей подтверждает целостность отчёта; сам факт визуального просмотра автоматически не подтверждается.

## Действия сценария

Неизвестные поля, действия и повторяющиеся ID отвергаются. Все шаги должны завершиться.

| Действие | Назначение |
| --- | --- |
| `capture` | Native PrintWindow клиентской области + дерево контролов. Другой способ отрисовки автоматически не подставляется |
| `click`, `select`, `text`, `toggle` | Настоящие обработчики / значения контролов |
| `hover`, `leave`, `focus` | События собственного контрола; физический курсор не используется |
| `key` | Одна клавиша без модификаторов: WM_KEYDOWN / WM_KEYUP конкретному контролу, для главного окна используется его обработчик навигации. Физический ввод, IME и глобальная маршрутизация Windows не проверяются |
| `assert`, `wait` | Текст, значение, доступность, фокус, флажок, позиция каретки; ожидание с таймаутом |
| `language`, `resize`, `scroll` | RU/EN, размер окна, Home/End/PageUp/PageDown списка |
| `reveal` | Прокрутить список к контролу. Взаимодействие с обрезанным или недоступным контролом даёт FAIL; `viewport` позволяет явно проверить видимость |
| `transition` | До действия, последовательность кадров, проверка изменения / установившегося состояния, итоговый снимок |
| `save-state`, `restore-state` | JSON виртуальных CPU / устройств / настроек и загрузка в интерфейс |
| `apply-model` | Общий DeviceSettingsWriter пишет в тестовый JSON; результат проверяется чтением файла |
| `model-error` | Реальный IOException в подставном хранилище, стек общего кода записи и настоящий диалог. Windows / драйвер не вызываются |
| `audit-editors` | Все видимые обычные поля в текущем наборе устройств: прокрутка до поля, нативный PNG, сравнение RGB-пикселей с более высоким эталоном, фокус и выход из поля. Сохраняет крупные планы и контекст карточек; неизвестный тип поля останавливает проверку |
| `gallery` | Существующая галерея тест-панели |

Выбор контрола: `@main`, `@active`, `id:ИМЯ`, `text:ПОДПИСЬ`. Для карточки укажите `device` с уникальной частью имени / Instance ID и `role:title`, `role:msi`, `role:limit`, `role:priority`, `role:policy`, `role:imod`, `role:imod-toggle`, `role:imod-check`, `role:imod-current`, `role:mode`. Несколько совпадений дают ошибку: нужно уточнить сценарий. Для переводимых кнопок используйте ID.

У перехода задаются `trigger`, `durationMs`, `intervalMs`, `requireChange`, `requireSettled`. Последние два включены по умолчанию. Если ожидаемого изменения нет или переход не завершился, проверка выдаёт FAIL. Кадры всё равно нужно оценить: это не автоматическая гарантия плавности.

Сохраняются минимум три настоящих кадра. При медленном захвате наблюдение может занять больше `durationMs`; фактическое время каждого кадра и интервалы записываются в `timelines`. Запрошенный интервал не выдаётся за достигнутую частоту кадров.

## Полная проверка

Сценарий [device-palette.json](Scenarios/device-palette.json) показывает палитру всех типов меток: GPU NVIDIA/AMD/Intel/неизвестный, NDIS/NetAdapterCx, USB, аудио и пять вариантов накопителей. Снимаются EN/RU и кадры переключения языка. Это отдельный визуальный сценарий; аппаратные устройства не используются.

Для просмотра меток GPU / NET рядом с USB и NVMe используйте отдельный сценарий [device-colors.json](Scenarios/device-colors.json). Он показывает настоящие карточки виртуальных устройств в EN/RU; Запускайте сценарий и сравнивайте результаты через `Invoke-DevSession.ps1`.

Отдельный сценарий [usb-role-order.json](Scenarios/usb-role-order.json) показывает все USB-роли на одном контроллере: заголовок EN/RU, переход языка и суженное окно. Запуск: `Invoke-DevSession.ps1 -Scenario .\dev\qa\Scenarios\usb-role-order.json`. Он нужен для просмотра порядка подписей и запускается отдельно от общего набора сценариев.

`Invoke-Qa.ps1` запускает 18 сценариев (`device-flow`, `control-states`, `dtimod-status`, `imod-check`, `imod-editor`, четыре `text-fields-*`, шесть `dialog-audit-*`, `backup-menu-flow`, `navigation-audit` и `irq-check-loading`) дважды и сравнивает контрольные снимки. Это проверка воспроизводимости текущей сборки. Далее идут галерея, RU/EN, модели масштаба, аудит ошибок и ресурсов; также выполняются тесты и намеренные поломки. `dtimod-status` использует общий код управления с подставными backends и открывает настоящие диалоги ошибок; драйвер не загружается.

Реестр / план питания / автозапуск / драйверы не изменяются и полностью не эмулируются. Новая функция должна получить свой сценарий и проверки общего технического кода на подставных данных. Покрытие новой функции автоматически не возникает.

`ui-controls` сравнивает пиксели букв в полях ввода и подписи "Аудио" с более высокими нативными контролами. Проверяются 0xFA0, нижние элементы латинских и русских букв, модели размера/шрифта 100/125/150%; намеренно обрезанные контролы обязаны отличаться. Это проверка полноты глифов, а не оценка шрифта или реальных переходов DPI Windows.

`text-fields-*` проверяют настоящие поля поиска, MSI Limit, IMOD, IMOD по ролям, NIC ITR и RSS в карточках четырёх наборов устройств: Intel, AMD, IMOD и NIC. Каждый сценарий проходит EN при 1200×900 и RU после сужения до 1000×720. Внутренний редактор сравнивается с более высоким полем той же ширины, текста, шрифта и цветов: проверяется вертикальная полнота символов, а не вместимость произвольно длинного ввода. Границы поля отдельно проверяются относительно видимой области. Снимки контекста нужны для визуальной оценки компоновки.

## Диалоги и меню

Сценарии `dialog-audit-en/ru` воспроизводят окна сохранения/восстановления, путь к файлу, проверку системы с известными и недоступными данными, подтверждения, выбор расположения бекапа, пустой/обычный/длинный список и результаты success/warnings/partial/failed/stress. Варианты `-120/-144` задают `layoutDpi` 120/144: это модели 125/150%, без изменения DPI Windows. `audit-dialog` сохраняет проверку высоты подписей, вместимости кнопок и границ окна.

`backup-menu-flow` проверяет удаление через подставной callback общего меню: сохранение окна, защиту исходного бекапа, пустой список, отказ/исключение, выбор оставшегося файла и полный путь. Реальные файлы бекапов не удаляются. `navigation-audit` открывает настоящие dropdown через F4, перемещается по пунктам и закрывает Escape, переключает категории в RU/EN.

`dialog` вызывает только разрешённые preview общих окон. `active:id:...` выбирает элемент активного вложенного окна; обычный `id:...` продолжает отвергать неоднозначность. Для формы Enter/Escape передаются её обработчику диалоговых клавиш; для остальных контролов используются собственные сообщения. Системный фокус и физический ввод не моделируются. Полный QA включает 18 сценариев дважды; наличие отчёта и MATCH не заменяют просмотра PNG.

В `transition` непустое `value` проверяет выбранное `property` у `target` перед действием и на каждом наблюдаемом кадре. Так `imod-check` проверяет постоянную надпись CHECK / ПРОВЕРИТЬ в течение повторного чтения. `check-presentation` отдельно сохраняет наведение, фокус, строки IRQ / HW и окно выбора бекапа в RU/EN. Кнопки категорий перемещают к устройствам, а строка поиска скрывает неподходящие карточки.

`irq-check-loading` нажимает общую кнопку СЧИТАТЬ IRQ в верхнем ряду в RU/EN: GPU и USB, успех, отказ и повтор. Только чтение оборудования подменено задержанным ответом. Проверяется ровно один запрос к каждому PCI-устройству, включая скрытые фильтром карточки. В каждом кадре проверяются тёмный фон технических блоков, доступность формы, блокировка кнопок и ровно один работающий индикатор. Драйвер не загружается.

`interface-wording` показывает главное окно, IMOD, параметры системы, восстановление и результаты в RU/EN. `dialog-audit-*` дополнительно проверяют отображение причин pre-restore, pre-release и сохранения IMOD/NIC ITR. Причины в самих JSON и имена файлов не переводятся.

`irq-field-layout` сравнивает поля IRQ Mode и строку навигации до/после изменения: RU/EN, GPU/USB, ширина 1200/1000. `irq-placement` дополнительно проверяет наведение и фокус обновления; `irq-toolbar-dense` проверяет вместимость поиска и категорий на насыщенном наборе устройств. В верхнем ряду четыре основных действия и общая кнопка чтения IRQ Mode.

`irq-control-states` показывает поле IRQ Mode и общую кнопку чтения в верхнем ряду: обычный вид, наведение, фокус и кадры чтения в RU/EN. Сценарий можно запускать с layoutDpi 96/120/144. `irq-glyph-errors` проверяет завершение состояния чтения после отказа и повторного запроса, вместимость русского статуса и общий охват PCI-устройств.

`irq-global-label` проверяет общую проверку через единую кнопку СЧИТАТЬ IRQ в верхнем ряду: скрытые PCI-устройства, отказ и повтор. Запуск с клавиатуры через общую кнопку обязан опросить тот же полный набор ровно по одному разу. Драйвер не загружается.

`irq-summary` проверяет верхний ряд из пяти кнопок: одна общая кнопка IRQ вне карточек, отсутствие пересечений и вместимость подписей, RU/EN, успех/отказ/повтор, общий охват PCI, клавиатура Space и ширина 1200/1000. Варианты layoutDpi 120/144 проверяют модели масштаба.

`irq-top-actions` сохраняет сравнение прежней полосы и общей кнопки READ IRQ MODE / СЧИТАТЬ IRQ в верхнем ряду: RU/EN, чтение, отказ, повтор, фокус и ширина 1200/1000. `irq-summary` отдельно проверяет, что в ряду ровно пять действий, подписи помещаются, а прежняя полоса отсутствует.
