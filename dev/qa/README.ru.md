# Проверки разработчика

[Разработка](../../docs/DEVELOPMENT.ru.md) · [English](README.md)

Модели оборудования и проверки интерфейса DEVICE TWEAKER без записи настроек на основном компьютере. Для воспроизведения достаточно исходников из Git. Созданные изображения, сборки и личные данные в репозиторий не входят.

## Выбор проверки

Для изменения интерфейса выполните один сценарий, просмотрите изображения и после правки повторите его с `-CompareWith`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Invoke-DevSession.ps1 -Scenario .\dev\qa\Scenarios\device-flow.json
```

Для скриншотов документации используется каталог галереи:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Export-Gallery.ps1
# Один вид на обоих языках:
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Export-Gallery.ps1 -Only gallery-usb-xhci
```

Команда сохраняет `index.html`, нативные PNG и `gallery.json` в `local/gallery`. Изображения в `assets/screenshots` не заменяются автоматически: сначала их нужно просмотреть.

Для логики приложения выбирайте соответствующие тесты из [tests/DeviceTweaker.Tests](tests/DeviceTweaker.Tests). Полный набор ниже нужен при сквозных изменениях. После каждой правки текста или небольшого визуального изменения его запускать не требуется.

## Полный скрытый QA

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Invoke-Qa.ps1
```

Команда собирает снимок исходников и выполняет unit-тесты, проверки с намеренными отказами, модель нативного драйвера и проверки интерфейса на скрытом рабочем столе. Это может занять несколько минут. Области покрытия, требования и результаты описаны в [справочнике проверок](Checks/README.ru.md).

## Остальные команды

- `Open-TestPanel.ps1`: вручную открыть разработческую панель в режиме read-only. Это интерактивная команда; автономная работа выполняется через скрытый workbench.
- `Review-DevSession.ps1`: записать визуальную оценку с привязкой к хешам просмотренных PNG.
- `Measure-IdleResources.ps1`: измерить процессорное время и расход памяти конкретного EXE в покое.
- `Test-ReleasePackage.ps1`: проверить файлы выпуска, встроенные зависимости и идентичность приложения.

Параметры, сценарии и примеры приведены в [руководстве workbench](WORKBENCH.ru.md). Подготовка выпуска описана в [RELEASE.ru.md](../../docs/RELEASE.ru.md).

## Структура каталога

- `Scenarios`: воспроизводимые действия и проверки GUI; в `Scenarios/Gallery` находятся скриншоты документации и их каталог.
- `tests`: изолированные тесты приложения и workbench с синтетическими данными.
- `Panel`: разработческая панель, модели устройств и подменённые аппаратные операции.
- `Workbench`: результаты сценариев, сравнение изображений и запись визуальной оценки.
- `Inspect`: консольный инспектор и проверки отрисовки контролов.
- `Checks`: проверки, вызываемые общим прогоном, и отдельная диагностика.
- `Support`: общие библиотеки изоляции, снимков исходников, кэша сборки и результатов. Это не самостоятельные команды.

## Границы и результаты

Интерфейс проверяется на скрытом рабочем столе Windows в режиме чтения. Запуски выполняются по одному, с ограничением памяти и остановкой при нехватке ресурсов хоста. Подготовка ручной тест-панели проходит через тот же защищённый worker; видимое окно открывается только при её явном интерактивном запуске. Настройки Windows не меняются, DTIMOD не загружается. В обычную сборку программы разработческая панель и workbench не входят.

Модели проверяют синтетическое оборудование, последовательности операций и ошибки. Они не подтверждают совместимость физического драйвера, поведение MMIO, реальный DPI монитора или производительность игр. Совпадение PNG подтверждает повторяемость; качество оформления оценивается после просмотра.

## Восстановление рабочей копии

Установите на Windows .NET SDK, выбранный в `global.json`, и запустите `Invoke-DevSession.ps1`. Прежнее содержимое `local`, пользовательские бэкапы, приватные сертификаты и готовые EXE не требуются. Для нативной модели дополнительно нужны C++ Build Tools и Windows SDK. Исходники QA и фикстуры храните в Git, результаты прогонов и личные данные оставляйте локально.
