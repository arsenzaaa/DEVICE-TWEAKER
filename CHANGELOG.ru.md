## 0.1.0

**DEVICE TWEAKER REWORK**.

Сравнение исходников: [v0.0.4 → v0.1.0](https://github.com/arsenzaaa/DEVICE-TWEAKER/compare/v0.0.4...v0.1.0).

### Сохранённые профили

- Профиль NIC ITR привязывается к конкретному экземпляру PCI-адаптера. Автозапуск пропускает старую запись, если она подходит нескольким адаптерам.
- При обновлении задачи сохраняется её состояние в Планировщике. При ошибке записи регистров задача возвращает код ошибки. Пропуски отмечаются отдельно в логе.
- Если при удалении общего профиля не удалось восстановить модерацию прерываний сетевого адаптера, профиль остаётся для повторной попытки. Задача автозапуска к этому моменту уже удалена.
- При сохранении NIC ITR карточка сообщает о незавершённой настройке модерации, если профиль сохранён, а чтение или запись параметра драйвера не удались.
- Если в бэкапе указан профиль автозапуска, а его содержимое отсутствует, восстановление останавливается до записи настроек. Сбой обновления списка устройств после восстановления отмечается отдельно.

### Подписи CPU, RSS и документация

- Исправлены подписи CPU на однородных процессорах: Core и Core/SMT вместо P-Core и P-Core/HT. Подписи гибридных CPU и правила распределения ядер сохранены.
- У адаптеров без MSI-X сохранён выбор числа очередей RSS из списка драйвера. Число очередей и число процессоров отслеживаются отдельно, в том числе при диагностике обратного чтения. АВТООПТИМИЗАЦИЯ выбирает минимальное число очередей из вариантов драйвера. Если списка нет, выбирается одна очередь.
- Политики, при которых CPU выбирает Windows, сохраняются без ручной маски. При записи RSS выставляется `*RSSProfile = 4` (`NUMAScalingStatic`, с сохранением в бэкап и очисткой при сбросе), чтобы на гибридных CPU Windows не оставалась в профиле `Balanced` и не игнорировала выбранный диапазон ядер; перед подтверждением RSS сверяются обе границы диапазона CPU с учётом групп процессоров.
- Маска `ReservedCpuSets` в `REG_BINARY` теперь выравнивается до кратности 8 байтам (64-битный `KAFFINITY` на группу процессоров), как требует `ntoskrnl`, с сохранением чтения старых коротких значений.
- Переработаны руководство и справочник настроек на английском и русском, убраны повторы и исправлены подписи в галерее. Скриншоты интерфейса обновлены с исправленными подписями CPU.

### Доступ через драйвер

- Удалён общий запрос DTIMOD для чтения произвольного физического адреса. Чтение регистров теперь привязано к конкретному PCI-устройству и проверяется по выделенным ему диапазонам MMIO. Чтение и запись MMIO разрешены только для классов xHCI и Ethernet.
- Точная карта interrupter для USB сохранена через отдельный запрос контекстов контроллера, возвращающий номера портов, USB-адреса и interrupter. Контексты в системной памяти читаются через `MmCopyMemory`, без отображения RAM как некэшируемой памяти устройства.
- Исправлен разбор ресурсов с дополнительными данными переменной длины DeviceSpecific. Убран неверный комментарий о том, что ссылка на устройство запрещает изменение его ресурсов; [ограничение PnP/питания](./docs/guide/11-driver.ru.md) сохраняется.
- Приложение и runtime автозапуска распознают старые загруженные сборки DTIMOD и требуют перезагрузку. SYS, встроенный хеш и манифест исходников обновлены вместе.

### Интерфейс и отзывчивость

- Главное окно учитывает рабочую область монитора при запуске и смене DPI.
- Кнопки в окнах результата, сообщений и выбора места бэкапа выровнены по центру; обновлена палитра меток устройств (включая более контрастный бейдж Intel USB), а в русской версии добавлен отступ между подписью и переключателем энергосбережения.
- Кнопки действий показывают локализованные статусы во время длительных операций, корректно переносятся на узких карточках при высоком DPI и аккуратно управляют фокусом при временной блокировке.
- **ОБНОВИТЬ** заново сканирует устройства и сохраняет совместимые карточки вместо полного пересоздания списка, удерживая неприменённые правки и положение прокрутки. При изменении топологии CPU список перестраивается заново.
- При обновлении списка выбранные CPU сохраняются вместе с политикой привязки или режимом RSS, даже если сохранённые настройки изменились. Сведения о драйверах для лога читаются независимо от обновления карточек.
- Приём Raw Input (`WM_INPUT`) перенесён с главного окна UI на отдельный фоновый поток (`HWND_MESSAGE`) с кэшированием расчёта частоты и ограниченной историей выборок: на устройствах 1K–8K интерфейс остаётся отзывчивым, а окно закрывается без задержек.
- Добавлены короткие плавные переходы для тумблеров, прокрутки и подсветки кнопок на базе общего таймера кадров с не более чем одним ожидающим обновлением UI; в покое таймер останавливается и не меняет разрешение системного таймера или параметры дисплея Windows.
- При неполном чтении IMOD последующие значения больше не отображаются под неверными номерами interrupter. В лог записываются индекс и адрес сбоя.

### Применение и сброс настроек

- ПРИМЕНИТЬ записывает только внесённые правки. Для применения изменений IMOD программа запрашивает разрешение на загрузку DTIMOD.
- ЗАДАТЬ применяет USB IMOD для выбранного контроллера. Новые записи профиля привязаны к экземпляру PCI. При ошибке или неполной записи прежний профиль автозапуска сохраняется.
- Применение USB IMOD через ЗАДАТЬ, ПРИМЕНИТЬ и АВТООПТИМИЗАЦИЮ автоматически раскрывает таблицу подробностей обратного чтения по interrupter на обновлённых контроллерах.
- ЗАДАТЬ и ПРИМЕНИТЬ отклоняют некорректные значения в полях USB IMOD для отдельных ролей до применения общей строки.
- УДАЛИТЬ ПРОФИЛЬ создаёт резервную копию и удаляет общий профиль автозапуска USB IMOD и NIC ITR. Команда также удаляет файл драйвера, если он соответствует этой сборке и больше не используется. Для сброса действующих значений регистров перезагрузите Windows.
- СБРОС ПО УМОЛЧАНИЮ восстанавливает исходные параметры выборочной приостановки USB для активной схемы питания.

### Автозапуск, восстановление и диагностика

- Оба способа загрузки DTIMOD проверяют файл драйвера. Пропуск USB IMOD в АВТООПТИМИЗАЦИИ сохраняет профиль.
- Если задача автозапуска не зарегистрировалась, программа сохраняет текущий профиль и возвращает заменённые файлы и задачу. Ошибки отката выводятся в результате операции.
- Чтение NIC ITR сохраняет правки, сделанные во время создания автоматического бэкапа.
- XML задачи планировщика создаётся в защищённой папке автозапуска. После регистрации проверяются число действий, команда и аргументы сохранённой задачи, а не просто наличие пути к скрипту в её тексте.
- Повторный запуск больше не переключает фокус на окно Проводника, открытое в папке с именем DEVICE TWEAKER.
- Переведены результаты восстановления, ошибки обнаружения устройств и диагностика схем питания, которые оставались английскими в русском интерфейсе.
- Обнаружение устройств продолжается при ошибке WMI-запроса Windows Storage (`MSFT_PhysicalDisk`): контроллеры NVMe и SATA/AHCI остаются в списке, а сбой записывается в лог.
- Чтение `AssignmentSetOverride` поддерживает значения `REG_BINARY` длиной 1–7 байт в порядке little-endian, а не только 4 и 8 байт, поэтому короткие маски привязки из реестра отображаются корректно.
- NIC ITR определяет базу регистров по PCI BAR, проверяет выделенные Windows диапазоны и исключает пересечение с таблицей/PBA MSI-X. Исправлены схемы Killer E3000 (`10EC:3000`) и RTL8118AS (`10EC:8162`).
- Восстановление бэкапа и установка автозапуска теперь одинаково обрабатывают устаревшие записи NIC ITR: несовместимая запись пропускается с предупреждением, а в лог записываются сохранённая и актуальная схемы регистров. Остальные записи и исходный бэкап сохраняются.
- Отключение MSI блокируется, если возможности PCI явно указывают на поддержку сообщений без линейных прерываний INTx. Отказ переведён на оба языка интерфейса.
- Восстановление отсутствующего значения реестра больше не создаёт ключ. Подготовка загрузчика использует права защищённой папки автозапуска не переключаясь на временный каталог.

### Сопровождение и QA

- Из MainForm выделены управление файлами автозапуска, работа с файлами и реестром резервных копий, сопоставление ролей USB, форматирование карты IMOD, подготовка файлов драйвера, запись параметров RSS и процесс KDU. Форматы профилей и резервных копий сохранены.
- Добавлены стенд GUI на скрытом рабочем столе (read-only), режимы QA `-Mode Fast` / `-Mode Full` с ограниченным кэшем сборок, нативные модели жизненного цикла C-драйвера и расширенный набор xUnit-тестов для ограниченного API драйвера, топологии USB, неполного чтения, компоновки карточек и UX-регрессий.

## [0.0.4](https://github.com/arsenzaaa/DEVICE-TWEAKER/releases/tag/v0.0.4) · 2026-10-31

Сравнение исходников: [v0.0.3 → v0.0.4](https://github.com/arsenzaaa/DEVICE-TWEAKER/compare/b82e8d095ac3303e0bcd8607ac291f0d3dc29bc1...v0.0.4).

### Изменено

- Автозапуск IMOD/NIC ITR перенесён в Планировщик заданий. Профиль применяется при входе в Windows, выходе из сна и подключении USB-устройства.

### Добавлено

- Программа и скрипт автозапуска используют общий код доступа к регистрам. Перед компиляцией проверяется SHA-256 общего кода. При загрузке DTIMOD проверяются файлы драйвера и загрузчика.
- Добавлены IRQ Mode и кнопка чтения IRQ для всех PCI-устройств. Текущий режим прерываний и возможности PCI отображаются отдельно от настройки MSI в реестре.
- Для RSS выбирается по одному логическому процессору на физическое ядро. Доступное число очередей учитывает ограничения драйвера и устройства.
- При сохранении NIC ITR отключаются поддерживаемые настройки собственной модерации сетевого драйвера; при удалении профиля предусмотрен возврат к значениям INF.
- Добавлена диагностика HVCI, Vulnerable Driver Blocklist, Microsoft Defender и служб FACEIT/Vanguard перед работой с драйвером.

### Исправлено

- Из DTIMOD.sys удалена общая команда записи в физическую память. Новая команда проверяет диапазон записи по ресурсам выбранного устройства.
- USB Selective Suspend восстанавливается через Windows Power API отдельно для питания от сети и батареи, с последующей проверкой значений.
- Для мыши отображается измеренная частота событий, в том числе когда она ниже максимума из USB-дескриптора.
- При восстановлении автоматическая очистка больше не удаляет выбранную копию и копию для отката. Ошибки восстановления питания устройства выводятся отдельно.
- Программа больше не перезаписывает профиль автозапуска, который не удалось прочитать или разобрать.
- После попытки загрузки драйвера с неопределённым результатом программа и скрипт автозапуска блокируют загрузку через резервный механизм.
- DTIMOD.sys отклоняет неполные списки аппаратных ресурсов, в том числе с повреждёнными данными после допустимого диапазона записи.

### Интерфейс

- Список бэкапов использует нейтральные цвета для выделенной строки, расположения файлов и защищённой исходной копии.
- В подсказке текущего IMOD показано время последнего чтения. После изменения состава устройств карта помечается как устаревшая.
- Статус Dual-CCD отображается как Вкл/Выкл.
- Длительные операции применения, сохранения, восстановления и сброса выполняются в фоне. Обновление списка сохраняет неприменённые изменения и положение прокрутки; при ошибке поиска устройств прежние карточки остаются на экране.
- Параметры RSS, энергосбережения и сведения о драйверах читаются в фоне. При ошибке или истечении времени ожидания сохраняется прежний список устройств; запоздавшие результаты игнорируются.
- Перестройка интерфейса сохраняет состояние карточек, фокус и положение курсора в поле ввода. После частичного применения неподтверждённые настройки остаются отмеченными как неприменённые.
- Английские и русские строки перенесены в файлы ресурсов. Уточнены сообщения об ошибках чтения настроек, повреждённых профилях и недопустимом MSI Limit.

### Сборка

- Исходники перенесены в `src`, инструменты QA собраны в `dev/qa`. Тест-панель включается только в DeveloperQa и отсутствует в обычном EXE.
- Приложение и инструменты сборки переведены на .NET 10. Сборка без встроенного .NET требует .NET 10 Desktop Runtime x64; автономная сборка включает среду выполнения.
- Workflow выпуска собирает выбранный коммит для проверки комплекта перед публикацией.
