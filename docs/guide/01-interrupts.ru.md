# Прерывания: ISR, DPC и ядра

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 01 · [English](./01-interrupts.md)

## От устройства к приложению

Прерывание сообщает процессору о событии устройства. Драйвер выполняет короткий ISR (обработчик прерывания), затем передаёт часть работы DPC (отложенной процедуре); приложение получает данные позднее. Путь обработки зависит от драйвера, API ввода и версии Windows.

```text
событие устройства → ISR → отложенная обработка драйвера → приложение
```

Драйвер может использовать несколько DPC и рабочих потоков. Механизм отложенной обработки описан в [Introduction to DPC objects](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/introduction-to-dpc-objects).

## IRQL и приоритет потока

IRQL определяет допустимые прерывания на текущем процессоре и отличается от приоритета потока Windows. Обычный ISR выполняется на DIRQL устройства, обычный DPC - на DISPATCH_LEVEL. При повышенном IRQL прерывания того же или меньшего уровня маскируются; более высокий уровень может прервать текущую обработку. См. [Managing hardware priorities](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/managing-hardware-priorities).

## На каком CPU выполняется работа

Interrupt Affinity задаёт политику назначения прерываний устройства. У DPC и рабочих потоков драйвера собственные целевые процессоры. По умолчанию DPC выполняется на CPU, на котором его поставили в очередь; драйвер может выбрать другой процессор. Правила описаны в [документации очередей DPC](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/organization-of-dpc-queues).

## Наблюдение за обработкой прерываний

DEVICE TWEAKER показывает сохранённую политику и текущие сведения о прерываниях. ETW-трасса записывает распределение ISR/DPC по процессорам и время выполнения обработчиков. Сбор трассы и сравнение результатов описаны в [главе проверки](./10-verification.ru.md).
