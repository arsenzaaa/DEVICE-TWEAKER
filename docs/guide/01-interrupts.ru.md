# Прерывания: ISR, DPC и ядра

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 01 · [English](./01-interrupts.md)

## От устройства к приложению

Прерывание сообщает о событии устройства. ISR (обработчик прерывания) выполняет срочную работу и может поставить в очередь DPC (отложенный вызов процедуры). Для дальнейшей обработки драйвер также может использовать рабочие потоки.

```text
событие устройства → ISR → отложенная обработка драйвера → приложение
```

## IRQL и приоритет потока

IRQL определяет, какие прерывания может принять логический процессор. При повышенном IRQL на нём маскируются прерывания текущего уровня и ниже. ISR обычно выполняется на уровне прерывания устройства. Обычный DPC выполняется на `DISPATCH_LEVEL`. Приоритет потока используется планировщиком при выборе готового к выполнению потока. См. *Windows Internals*, 7-е изд., ч. 1, с. 488–492, и [Managing hardware priorities](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/managing-hardware-priorities).

## На каком CPU выполняется работа

Interrupt Affinity задаёт политику назначения прерываний устройства. Когда ISR ставит DPC в очередь, по умолчанию используется текущий CPU. Драйвер может выбрать очередь другого CPU. Рабочие потоки планируются отдельно. См. [документацию по очередям DPC](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/organization-of-dpc-queues).

## Наблюдение за обработкой прерываний

Начните с трассы под нагрузкой при исходных настройках. В [главе о проверке](./10-verification.ru.md) показано, как найти модуль драйвера и сравнить распределение ISR/DPC до и после изменения привязки.
