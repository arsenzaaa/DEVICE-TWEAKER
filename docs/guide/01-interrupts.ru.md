# Прерывания: ISR, DPC и ядра

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 01 · [English](./01-interrupts.md)

## От устройства к приложению

Прерывание сообщает процессору о событии устройства. Типичный драйвер быстро обслуживает его в ISR, затем откладывает часть работы в DPC; приложение получает данные позднее. Путь обработки зависит от драйвера, API ввода и версии Windows.

```text
событие устройства → ISR → отложенная обработка драйвера → приложение
```

Драйвер может использовать несколько DPC и рабочих потоков. Механизм отложенной обработки описан в [Introduction to DPC objects](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/introduction-to-dpc-objects).

## IRQL и приоритет потока

IRQL определяет допустимые прерывания на текущем процессоре и отличается от приоритета потока Windows. Обычный ISR выполняется на DIRQL устройства, обычный DPC - на DISPATCH_LEVEL. При повышенном IRQL прерывания того же или меньшего уровня маскируются; более высокий уровень может прервать текущую обработку. См. [Managing hardware priorities](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/managing-hardware-priorities).

[Threaded DPC](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/introduction-to-threaded-dpcs) могут выполняться на PASSIVE_LEVEL. Контекст выполнения определяется по данным событий в трассе.

## На каком CPU выполняется работа

Interrupt Affinity задаёт политику назначения прерываний устройства. Она не устанавливает affinity всех потоков этого драйвера. У DPC есть целевой процессор: по умолчанию это CPU, на котором DPC поставили в очередь, но драйвер может выбрать другой. См. [Organization of DPC queues](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/organization-of-dpc-queues).

Поэтому перенос ISR и перенос всей обработки устройства - разные результаты. Важны фактическое распределение работы, длительность обработчиков и конкуренция с приложением.

## Что проверять после настройки

DEVICE TWEAKER показывает сохранённую политику и доступные сведения о текущих прерываниях. Для проверки размещения ISR/DPC нужен отдельный ETW-трейс. Маска в интерфейсе, один показатель FPS или максимальная длительность одного DPC не доказывают улучшения задержки ввода.

Сначала сохраните исходные условия, затем сравните одинаковую нагрузку до и после изменения. Порядок проверки - в [главе 10](./10-verification.ru.md).
