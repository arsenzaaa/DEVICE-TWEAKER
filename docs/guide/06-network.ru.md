# Сеть: RSS, NDIS и NIC ITR

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 06 · [English](./06-network.md)

## Драйвер и режим affinity

В карточке NDIS выберите **RSS** для настройки CPU и очередей приёма, **IRQ** для привязки прерываний или **BOTH** для обоих механизмов, если адаптер поддерживает RSS. Заполните поля выбранного режима и нажмите **ПРИМЕНИТЬ**. В DEVICE TWEAKER поля RSS есть в карточках NDIS. [Драйверы NetAdapterCx тоже могут поддерживать RSS](https://learn.microsoft.com/en-us/windows-hardware/drivers/netcx/netadaptercx-receive-side-scaling-rss-).

## Что делает RSS

RSS распределяет потоки входящего трафика по CPU с помощью хеша и таблицы перенаправления. Драйвер с [одной аппаратной очередью](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/rss-with-a-single-hardware-receive-queue) может после прерывания передать обработку пакетов другим CPU. При поддержке MSI-X адаптер может направить прерывание на CPU, который будет обрабатывать данные. При настройке обоих механизмов проверьте по трассе и прерывания, и обработку пакетов.

Поле **Очереди RSS** задаёт запрашиваемое число приёмных очередей. При выборе CPU программа берёт по одному логическому процессору на физическое ядро в пределах возможностей адаптера. Например, если CPU 9 делит ядро с CPU 8, то при двух очередях и двух доступных ядрах программа может выбрать CPU 8 и CPU 10. Несколько очередей могут обслуживаться одним CPU, как у некоторых [адаптеров Intel I219](https://www.intel.com/content/www/us/en/support/articles/000017506/network-and-io.html).

AUTO запрашивает наименьшее число из списка драйвера. Если драйвер предлагает две и четыре очереди, AUTO запросит две. При отсутствии списка запрашивается одна. Трафик одного соединения может идти через одну очередь даже при нескольких включённых.

После нажатия **ПРИМЕНИТЬ** лог сверяет с действующей конфигурацией RSS сохранённое число очередей, число процессоров и обе границы диапазона CPU (с учётом групп процессоров). Если значения расходятся, повторите проверку после перезагрузки Windows. Чтобы прочитать действующую конфигурацию, выполните в PowerShell:

```powershell
Get-NetAdapterRss -Name "<имя адаптера>" |
    Format-List *
```

Большее число CPU может увеличить накладные расходы, не улучшив пропускную способность. Microsoft рекомендует подбирать его по нагрузке: [Setting the number of RSS processors](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/setting-the-number-of-rss-processors). Сравнивайте число очередей на трафике того приложения, которое настраиваете.

## NIC ITR

ITR управляет аппаратной модерацией прерываний поддерживаемого контроллера. **ЗАДАТЬ** применяет значение сейчас, **СОХРАНИТЬ** записывает профиль автозапуска, **ПРОВЕРИТЬ** перечитывает регистры. Для неизвестных PCI ID запись заблокирована.

**СОХРАНИТЬ** привязывает запись к экземпляру PCI-устройства. В старых профилях использовался идентификатор модели. Если при автозапуске такая запись подходит нескольким подключённым адаптерам, скрипт её пропускает. Чтобы настроить каждый адаптер отдельно, сохраните значения в его карточке.

Профили Intel EITR/ITR и Realtek IntrMit используют разные регистры и единицы измерения. Допустимый диапазон зависит от семейства адаптера. Нажмите **ПРОВЕРИТЬ**, чтобы считать текущие значения.

Адаптивная модерация драйвера может перезаписать значение ITR. **СОХРАНИТЬ** отключает поддерживаемые параметры модерации в реестре. Драйвер читает эти параметры при запуске адаптера. Команда [УДАЛИТЬ ПРОФИЛЬ](./05-usb-imod.ru.md#удаление-и-восстановление) удаляет профиль и возвращает применимые значения по умолчанию.

Если после **СОХРАНИТЬ** карточка сообщает, что настройка модерации не завершена, профиль автозапуска уже записан. В логе указано, какой параметр драйвера не удалось прочитать или изменить.

База регистров NIC ITR определяется по конфигурации PCI и сверяется с диапазонами памяти, выделенными Windows. При недоступных или несогласованных ресурсах, а также при пересечении диапазона регистров с таблицей MSI-X или PBA (Pending Bit Array) доступ отклоняется.

При установке профиля или восстановлении бэкапа программа сверяет каждую запись NIC ITR с текущей схемой регистров для её PCI ID. Несовместимые записи пропускаются. В окне восстановления и в логе указывается соответствующий адаптер. Сохраните NIC ITR для него заново. Исходный бэкап остаётся доступен.

## Проверка результата

Адаптеры Wi-Fi исключены из автооптимизации и сброса настроек проводной сети. При одинаковом трафике сравните активный RSS, считанные значения ITR, потери пакетов, нагрузку CPU и задержку. Уменьшение модерации может увеличить частоту прерываний и нагрузку.

Трассировка сетевой обработки и сравнение результатов описаны в [главе о проверке результата](./10-verification.ru.md).
