# Сеть: RSS, NDIS и NIC ITR

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 06 · [English](./06-network.md)

## Драйвер и режим affinity

DEVICE TWEAKER различает NDIS и NetAdapterCx и показывает доступные настройки конкретного адаптера. Для NDIS предусмотрены RSS, IRQ и совместный режим. Доступность функций и путь обработки зависят от адаптера и драйвера.

RSS распределяет обработку приёма между CPU, а Interrupt Affinity задаёт назначение прерываний. В режиме BOTH настраиваются оба механизма.

В карточке NDIS выберите **RSS** для процессоров и очередей приёма, **IRQ** для interrupt affinity или **BOTH** для обоих механизмов, если RSS поддерживается. Укажите CPU и число очередей, затем нажмите **ПРИМЕНИТЬ**. В карточке NetAdapterCx доступны поля для этого типа адаптера. У NIC ITR отдельные команды ЗАДАТЬ/СОХРАНИТЬ, описанные ниже.

## Что делает RSS

RSS распределяет приём сетевых данных между CPU; связь пакетов с процессорами определяется хешированием и таблицей перенаправления. Возможности отличаются: Microsoft описывает варианты с одной или несколькими аппаратными очередями и с MSI. См. [Introduction to receive-side scaling](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/introduction-to-receive-side-scaling).

Драйвер может планировать receive DPC на целевых процессорах. См. [Receive-side scaling support](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/receive-scaling). Наличие нескольких очередей не означает, что один поток соединения загрузит их все.

В приложении выбираются физические ядра с учётом SMT, число очередей и доступные ограничения адаптера. Карточка сравнивает сохранённые параметры с активным состоянием RSS и показывает расхождения.

**RSS Queues** задаёт число приёмных очередей. DEVICE TWEAKER выбирает физические ядра для RSS, пропуская SMT-соседей и учитывая известные ограничения адаптера. Несколько очередей могут использовать одни и те же доступные ядра. Например, если CPU 9 - SMT-сосед CPU 8, две очереди выбирают CPU 8 и CPU 10. При настройке RSS через AUTO используется одна очередь на одном физическом ядре.

Количество очередей может отличаться от числа процессоров. [Intel I219 и родственные адаптеры](https://www.intel.com/content/www/us/en/support/articles/000017506/network-and-io.html) поддерживают до двух приёмных очередей, обслуживаемых одним ядром. Программа сохраняет такие варианты, объявленные драйвером; если список вариантов недоступен, для адаптера без MSI-X используется одна очередь.

```powershell
Get-NetAdapterRss -Name "<имя адаптера>" |
    Format-List *
```

Большее число CPU может увеличить накладные расходы, не улучшив пропускную способность. Microsoft рекомендует подбирать его по нагрузке: [Setting the number of RSS processors](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/setting-the-number-of-rss-processors). Сравнивайте число очередей на трафике того приложения, которое настраиваете.

## NIC ITR

ITR управляет аппаратной модерацией прерываний поддерживаемого контроллера. **ЗАДАТЬ** применяет значение сейчас, **СОХРАНИТЬ** записывает профиль автозапуска, **ПРОВЕРИТЬ** перечитывает регистры. Для неизвестного PCI ID запись закрыта.

Профили Intel EITR/ITR и Realtek IntrMit используют разные регистры и единицы. Диапазон указан в описании выбранного семейства; ПРОВЕРИТЬ показывает текущие значения регистров.

При ручном ITR адаптивная модерация драйвера может перезаписывать регистр. Программа учитывает доступные параметры драйвера и возвращает управление ему при удалении сохранённого профиля. Подробности и неподтверждённые шаги отражаются в результате операции.

База регистров NIC ITR определяется по конфигурации PCI и сверяется с диапазонами памяти, выделенными Windows. Недоступные или несогласованные ресурсы и пересечение регистров с таблицей MSI-X или массивом ожидающих прерываний отклоняются.

При установке профиля и восстановлении бэкапа записи NIC ITR сверяются с текущей схемой регистров для каждого PCI ID. Несовместимые записи пропускаются с предупреждением; обе схемы записываются в лог. Для такого адаптера сохраните NIC ITR заново. Остальные поддерживаемые записи и исходный бэкап сохраняются.

## Проверка результата

Wi-Fi исключён из AUTO и сброса поддерживаемых проводных настроек. Для проводной сети сравнивайте активный RSS, readback ITR, потери пакетов, загрузку CPU и задержку под одинаковым трафиком. Уменьшение модерации может увеличить частоту прерываний и нагрузку.

Трассировка сетевой обработки и сравнение результатов описаны в [главе проверки](./10-verification.ru.md).
