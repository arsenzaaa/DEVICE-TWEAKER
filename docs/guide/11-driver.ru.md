# DTIMOD.sys, KDU и автозапуск

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 11 · [English](./11-driver.md)

## Для каких операций нужен DTIMOD

DTIMOD используется для USB IMOD, NIC ITR и дополнительных сведений из конфигурации PCI. MSI, interrupt affinity, RSS, ReservedCpuSets, Mouse Throttle и настройки питания устройств работают без него. Часть сведений [IRQ Mode](./02-msi.ru.md) берётся из ресурсов Windows; драйвер позволяет получить дополнительные данные устройства.

## Загрузка через KDU

У DTIMOD нет публичной подписи Microsoft для обычной загрузки. Проект использует закреплённую версию [KDU](../../src/IMOD/KDU/README.ru.md), которая опирается на уязвимый подписанный драйвер. Это аппаратный инструмент с высокими привилегиями; антивирус, HVCI, Vulnerable Driver Blocklist и античит могут препятствовать его работе.

DTIMOD может конфликтовать с Easy Anti-Cheat, Riot Vanguard, FACEIT Anti-Cheat и другими средствами защиты. Успешная загрузка драйвера не подтверждает совместимость: игра может отключить от сеанса, пока драйвер загружен. При загруженном DTIMOD EAC может отключить от игры с ошибкой `Forbidden Tool`. Совместимость с Vanguard и FACEIT не установлена.

Перед использованием драйвера или сохранением/восстановлением его профиля программа один раз за запуск показывает предупреждение. В AUTO оно включено в вопрос об IMOD. **О ДРАЙВЕРЕ** читает доступные параметры Windows и сведения об отдельных службах, не загружая DTIMOD. Эта проверка не определяет совместимость; отсутствие записи реестра или службы не означает, что система разрешает драйвер. Подробности записываются в лог. После ошибки загрузки программа не предлагает отключать защиту Windows.

Программа проверяет закреплённые хеши файлов и блокирует резервный механизм загрузки после попытки с неопределённым результатом. Причина указана в подробностях операции. Для замены уже загруженной старой версии или выгрузки DTIMOD перезагрузите Windows; закрытие EXE только закрывает подключение.

## Сохранённый профиль

Программа использует задачу `\DEVICE TWEAKER\IMOD` от SYSTEM с триггерами входа, пробуждения и соответствующих PnP-событий. Файлы находятся здесь:

```text
%ProgramData%\DEVICE TWEAKER\Startup
  ApplyIMOD.ps1
  DeviceTweakerImodRuntime.cs
  profile.json
  Loader\
  logs\
```

Runtime общий для приложения и Windows PowerShell 5.1. Его SHA-256 проверяется перед компиляцией; файлы DTIMOD и загрузчика проверяются при загрузке драйвера. Общий mutex исключает одновременную загрузку из приложения и startup-скрипта. Каталог защищён правами администраторов/SYSTEM. Для startup logs сохраняются последние 14 файлов.

Задача работает независимо от EXE. При ошибке чтения или разбора профиль сохраняется без изменений. **УДАЛИТЬ** в блоке IMOD удаляет общий автозапуск USB IMOD и NIC ITR, включая задачу Планировщика.

Если старая запись NIC ITR больше не соответствует поддерживаемой схеме регистров, восстановление пропускает её с предупреждением. Сохраните NIC ITR для этого адаптера заново. Подробнее: [совместимость профилей NIC](./06-network.ru.md#nic-itr).

## Состояние контроллера во время доступа к регистрам

Во время доступа к регистрам PCI-контроллер должен оставаться подключённым и работающим. Это относится и к применению startup-профиля. Переподключение мыши или клавиатуры при работающем USB-контроллере - другое событие.

DTIMOD проверяет адреса по выделенным контроллеру диапазонам MMIO, но не синхронизирует доступ с переходами PnP и питания Windows. Ресурсы могут измениться при [неожиданном удалении](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/handling-an-irp-mn-surprise-removal-request) или [остановке/перераспределении](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/handling-an-irp-mn-stop-device-request--windows-2000-and-later-). Проверка диапазона не покрывает одновременное удаление контроллера или изменение его состояния питания.

## Доступ к регистрам и карта USB

Чтение и запись регистров привязаны к PCI-устройству, ограничены его выделенными диапазонами MMIO и разрешены для классов xHCI (`0C0330`) и Ethernet (`0200`). Read-only запросы конфигурации PCI также используются для проверки IRQ у других классов устройств.

Для точной карты USB отдельный запрос xHCI возвращает номера корневых портов, USB-адреса и interrupter. Внутренний обход читает контексты контроллера и данные колец передачи из системной памяти через [MmCopyMemory](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-mmcopymemory). Запрос не принимает произвольный адрес RAM и возвращает разобранную топологию. Остальные границы доступа описаны в [политике безопасности](../../.github/SECURITY.ru.md).

## Проверка и восстановление

Сверьте SHA-256 EXE с `SHA256SUMS.txt` из того же набора выпуска. SHA исходного коммита в описании выпуска указывает на соответствующий код. Совпадение хешей подтверждает соответствие набору, но не поведение драйвера на вашем оборудовании.

После аппаратного изменения нужны readback и проверка устройства, включая сон и переподключение. Локальный QA не выполняет такую проверку: он использует модели и настоящий запрет записи. Сохраняйте исходный профиль и резервную копию до эксперимента.
