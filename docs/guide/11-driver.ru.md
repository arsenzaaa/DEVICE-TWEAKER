# DTIMOD.sys, KDU и автозапуск

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 11 · [English](./11-driver.md)

## Для каких операций нужен DTIMOD

DTIMOD.sys обеспечивает аппаратный доступ к поддерживаемым регистрам USB IMOD и NIC ITR и дополнительным сведениям PCI. Чтение и запись регистров привязаны к конкретному PCI-устройству, проверяются по выделенным ему диапазонам MMIO и разрешены только для классов xHCI (`0C0330`) и Ethernet (`0200`). Прежние запросы произвольного чтения и записи физической памяти отклоняются. Чтение конфигурации PCI для определения IRQ остаётся доступно и для других классов устройств.

Для точной карты USB используется отдельный запрос xHCI. Драйвер проходит по DCBAA, контекстам устройств и данным endpoint/TRB контроллера и возвращает только номера корневых портов, USB-адреса устройств и interrupter. Эти структуры находятся в системной памяти, поэтому внутреннее чтение выполняется через [MmCopyMemory](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-mmcopymemory), без отображения RAM как некэшируемой памяти устройства. Запрос не принимает произвольный адрес RAM от вызывающего процесса и не возвращает сырые байты контекстов. Это остаётся привилегированным доступом к оборудованию, а не границей изоляции от администратора, управляющего устройством.

MSI, affinity, RSS, ReservedCpuSets, Mouse Throttle и доступные параметры питания не требуют DTIMOD. Часть сведений IRQ Mode читается из ресурсов Windows без драйвера; доступный драйвер помогает получить дополнительные данные. Неполное определение режима не следует путать с ошибкой записи настройки.

## Состояние контроллера во время доступа к регистрам

Перед доступом к регистру DTIMOD сверяет адрес со снимком выделенных устройству диапазонов MMIO. Чтение и запись регистров не согласованы с PnP-событиями и изменением состояния питания целевого контроллера. Проверка диапазона не гарантирует действительность ресурсов при остановке, удалении контроллера или переназначении ресурсов. Ссылка сохраняет объект устройства, а не его аппаратные ресурсы: Windows может освободить их при [неожиданном удалении](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/handling-an-irp-mn-surprise-removal-request) или [остановке для перераспределения ресурсов](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/handling-an-irp-mn-stop-device-request--windows-2000-and-later-).

Не отключайте, не перезапускайте и не извлекайте целевой PCI-контроллер во время операций с регистрами, в том числе при фоновом применении сохранённого профиля. Отключение USB-периферии при остающемся на месте контроллере - другое событие. Безопасная обработка одновременного удаления контроллера или изменения его состояния питания для этого драйвера не установлена.

## Загрузка через KDU

У DTIMOD нет публичной подписи Microsoft для обычной загрузки. Проект использует закреплённую версию [KDU](../../src/IMOD/KDU/README.md), которая опирается на уязвимый подписанный драйвер. Это аппаратный инструмент с высокими привилегиями; антивирус, HVCI, Vulnerable Driver Blocklist и античит могут препятствовать его работе.

DTIMOD может конфликтовать с Easy Anti-Cheat, Riot Vanguard, FACEIT Anti-Cheat и другими средствами защиты. Успешная загрузка драйвера не подтверждает совместимость: игра может отключить от сеанса, пока драйвер загружен. На проверенной системе при загруженном DTIMOD воспроизведены отключения EAC с `Forbidden Tool`. Совместимость с Vanguard и FACEIT не установлена.

Перед использованием драйвера или сохранением/восстановлением его профиля программа один раз за запуск показывает предупреждение. В AUTO оно включено в вопрос об IMOD. **О ДРАЙВЕРЕ** читает доступные параметры Windows и сведения об отдельных службах, не загружая DTIMOD. Эта проверка не определяет совместимость; отсутствие записи реестра или службы не означает, что система разрешает драйвер. Подробности записываются в лог. После ошибки загрузки программа не предлагает отключать защиту Windows.

Программа проверяет закреплённые хеши файлов и блокирует резервный механизм загрузки после попытки с неопределённым результатом. Причина указана в подробностях операции. Для замены уже загруженной старой версии или выгрузки DTIMOD перезагрузите Windows; закрытие EXE только закрывает подключение.

## Сохранённый профиль

Программа использует задачу `\DEVICE TWEAKER\IMOD` от SYSTEM с триггерами входа, пробуждения и соответствующих PnP-событий. Файлы находятся здесь:

```text
%ProgramData%\DEVICE TWEAKER\Startup
  ApplyIMOD.ps1
  DeviceTweakerImodRuntime.cs
  profile.json
  Loader\
  logs\
```

Runtime общий для приложения и Windows PowerShell 5.1. Его SHA-256 проверяется перед компиляцией; файлы DTIMOD и загрузчика проверяются при загрузке драйвера. Общий mutex исключает одновременную загрузку из приложения и startup-скрипта. Каталог защищён правами администраторов/SYSTEM. Для startup logs сохраняются последние 14 файлов.

Задача работает независимо от EXE. При ошибке чтения или разбора профиль сохраняется без изменений. **УДАЛИТЬ** в блоке IMOD удаляет общий автозапуск USB IMOD и NIC ITR, включая задачу Планировщика.

## Проверка и восстановление

Сверьте SHA-256 EXE с `SHA256SUMS.txt` из того же набора выпуска. SHA исходного коммита в описании выпуска указывает на соответствующий код. Совпадение хешей подтверждает соответствие набору, но не поведение драйвера на вашем оборудовании.

После аппаратного изменения нужны readback и проверка устройства, включая сон и переподключение. Локальный QA не выполняет такую проверку: он использует модели и настоящий запрет записи. Сохраняйте исходный профиль и резервную копию до эксперимента.
