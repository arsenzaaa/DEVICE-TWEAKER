# DTIMOD.sys, KDU и автозапуск

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 11 · [English](./11-driver.md)

## Для каких операций нужен DTIMOD

DTIMOD.sys обеспечивает аппаратный доступ к поддерживаемым регистрам USB IMOD и NIC ITR и дополнительным сведениям PCI. Запись ограничивается проверяемыми диапазонами MMIO выбранного устройства; общий интерфейс произвольной записи в физическую память не предоставляется.

MSI, affinity, RSS, ReservedCpuSets, Mouse Throttle и доступные параметры питания не требуют DTIMOD. Часть сведений IRQ Mode читается из ресурсов Windows без драйвера; доступный драйвер помогает получить дополнительные данные. Неполное определение режима не следует путать с ошибкой записи настройки.

## Загрузка через KDU

У DTIMOD нет публичной подписи Microsoft для обычной загрузки. Проект использует закреплённую версию [KDU](../../src/IMOD/KDU/README.md), которая опирается на уязвимый подписанный драйвер. Это аппаратный инструмент с высокими привилегиями; антивирус, HVCI, Vulnerable Driver Blocklist и античит могут препятствовать его работе.

**ПРОВЕРКА СИСТЕМЫ** показывает доступные сведения о защитных механизмах и службах, не загружая драйвер. Отсутствие найденной службы не является гарантией совместимости античита. Не отключайте защиту только ради получения зелёного статуса в приложении; остальные функции доступны без загрузчика.

Программа проверяет закреплённые хеши файлов и блокирует резервный механизм загрузки после попытки с неопределённым результатом. Причина указана в подробностях операции. Для замены уже загруженной старой версии или выгрузки DTIMOD перезагрузите Windows; закрытие EXE только закрывает подключение.

## Сохранённый профиль

Программа использует задачу `\DEVICE TWEAKER\IMOD` от SYSTEM с триггерами входа, пробуждения и соответствующих PnP-событий. Файлы находятся здесь:

```text
%ProgramData%\DEVICE TWEAKER\Startup
  ApplyIMOD.ps1
  DeviceTweakerImodRuntime.cs
  profile.json
  Loader\
  logs\
```

Runtime общий для приложения и Windows PowerShell 5.1. Перед применением проверяются хеши файлов; общий mutex исключает одновременную загрузку из приложения и startup-скрипта. Каталог защищён правами администраторов/SYSTEM. Для startup logs сохраняются последние 14 файлов.

Задача работает независимо от EXE. При ошибке чтения или разбора профиль сохраняется без изменений. **УДАЛИТЬ** в блоке IMOD удаляет общий автозапуск USB IMOD и NIC ITR, включая задачу Планировщика.

## Проверка и восстановление

Сверьте SHA-256 EXE с `SHA256SUMS.txt` из того же набора выпуска. `SOURCE-SHA256SUMS.txt` описывает соответствующие исходники. Совпадение хешей подтверждает соответствие набору, но не поведение драйвера на вашем оборудовании.

После аппаратного изменения нужны readback и проверка устройства, включая сон и переподключение. Локальный QA не выполняет такую проверку: он использует модели и настоящий запрет записи. Сохраняйте исходный профиль и резервную копию до эксперимента.
