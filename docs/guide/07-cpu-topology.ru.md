# Топология процессора и ReservedCpuSets

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 07 · [English](./07-cpu-topology.md)

## Как читать список CPU

Карточки показывают логические CPU, физические ядра, SMT-соседей и доступные сведения о P/E-ядрах, CCD/CCX и CPPC. Например, `CPU 6 (P-Core, R131, #4)` и `CPU 7 (P-Core/HT, R131, #4)` относятся к одному физическому ядру.

CPPC-рейтинг - относительная подсказка прошивки, а не замер быстродействия приложения. CCD/CCX и кэш помогают описать топологию; переход между ними не имеет одной постоянной цены для всех процессоров и нагрузок.

## Как AUTO использует топологию

AUTO выбирает целевой CCD и физические ядра по правилам проекта, учитывает SMT и доступные рейтинги. Для GPU используется пара физических ядер; другие роли получают свои назначения. Ненадёжное определение необходимой топологии блокирует соответствующую автоматическую запись.

AUTO меняет настройки устройств, сохраняя SMT, E-cores и привязку игровых потоков. Назначения ядер зависят от обнаруженной топологии; сравнивайте производительность на своей нагрузке.

## ReservedCpuSets

Отдельная панель работает со значением:

```text
HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Kernel
  ReservedCpuSets  REG_BINARY
```

Изменение сначала остаётся ожидающим и записывается при **ПРИМЕНИТЬ**, после резервной копии. Если запись не удалась, ожидающее состояние сохраняется. При отсутствии надёжных CPU Set IDs панель недоступна.

Не смешивайте это значение с API назначения CPU Sets отдельному процессу. В [документации CPU Sets](https://learn.microsoft.com/en-us/windows/win32/procthread/cpu-sets) описаны CPU Set IDs, ограничения affinity и политики резервирования; она не гарантирует изоляцию всех ISR/DPC через эту настройку реестра.

Резервирование не доказывает, что на CPU исчезли системные события или что игра автоматически получила нужные ядра. Проверяйте планирование и прерывания на своей сборке Windows, сохраняйте исходную маску и учитывайте поведение после перезагрузки.

## Практическая проверка

Проверьте соответствие выбранных CPU физическим ядрам, затем сравните размещение ISR/DPC и потоков приложения. Не считайте два SMT-соседа двумя независимыми физическими ядрами. Эффект совместной загрузки SMT-соседей оценивайте измерениями своей нагрузки.
