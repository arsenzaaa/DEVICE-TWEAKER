# Топология процессора и ReservedCpuSets

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 07 · [English](./07-cpu-topology.md)

## Как читать карту процессора

DEVICE TWEAKER запрашивает топологию Windows (`GetSystemCpuSetInformation` и таблицы связей процессоров), чтобы сопоставить логические CPU с физическими ядрами, доменами кэша и рейтингами прошивки:

- На **однородных CPU** два логических потока одного физического ядра помечаются как `Core` и `Core/SMT` (например, `CPU 6 (Core, R131, #4)` и `CPU 7 (Core/SMT, R131, #4)` относятся к одному физическому ядру).
- На **гибридных CPU** `P-Core` и `E-Core` различаются по `EfficiencyClass` и наличию SMT-пары.
- **Рейтинги CPPC** отражают оценку прошивки, какие ядра лучше держат частоты буста.
- **CCD / CCX и домены L3** (`LastLevelCacheIndex`) разделяют чиплеты на многочиплетных процессорах, где перенос данных между CCD добавляет межчиплетную задержку.

Учитывайте разницу между потоками и прерываниями на SMT. Планировщик потоков Windows сам предпочитает свободное физическое ядро занятому SMT-соседу (*Windows Internals*, 7-е изд., ч. 1, гл. 4), поэтому обычные потоки естественно разносятся по разным физическим ядрам, пока есть свободные. Аппаратные прерывания и DPC этим правилам **не подчиняются**: прерывание приходит на назначенный логический CPU независимо от того, что выполняется на его SMT-соседе.

## Как AUTO использует топологию

**АВТООПТИМИЗАЦИЯ** выбирает целевой CCD и распределяет физические ядра с учётом SMT, классов ядер и рейтингов CPPC: пара соседних физических ядер для дискретной GPU, штатное распределение Windows для встроенной графики и отдельные правила для ввода, проводной сети и звука. Если нужные сведения о топологии определить ненадёжно, AUTO пропускает запись соответствующих масок вместо того, чтобы гадать.

AUTO меняет только настройки устройств — оно не отключает SMT, не трогает E-ядра и не меняет привязку игровых потоков.

## ReservedCpuSets

Панель **Reserved CPU Sets** задаёт общесистемное резервирование ядер через механизм **CPU Sets**. В отличие от жёсткой маски `SetProcessAffinityMask`, CPU Sets работают как мягкое ограничение планировщика и **действуют в том числе на системные потоки**: зарезервированные логические CPU получают флаг `Allocated` в `SYSTEM_CPU_SET_INFORMATION`, освобождаются от обычной фоновой нагрузки и не уходят в парковку. При этом Windows всё равно запустит поток на зарезервированном ядре, если поток явно привязан туда через affinity или CPU Set.

Маска резервирования хранится в реестре в формате `REG_BINARY` (little-endian), выровненном до кратности 8 байтам (по одной 64-битной маске `KAFFINITY` на группу процессоров, как требует `ntoskrnl`):

```text
HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Kernel
  ReservedCpuSets  REG_BINARY
```

Отметьте нужные логические CPU и нажмите **ПРИМЕНИТЬ** (снятие всех отметок с последующим применением удаляет параметр из реестра). Панель активна только тогда, когда идентификаторы CPU Set определены надёжно; перед записью создаётся бэкап, а при ошибке записи правки остаются неприменёнными.

> **Не смешивайте в жёсткой маске affinity одного процесса зарезервированные и незарезервированные CPU.** Как следует из модели CPU Sets (*Windows Internals*, 7-е изд., ч. 1, с. 278–283), пересечение обоих пулов в одной жёсткой маске приводит к непредсказуемому планированию. Обычные процессы должны оставаться на незарезервированном пуле, а зарезервированные ядра имеет смысл выделять только под конкретную целевую нагрузку.

**АВТООПТИМИЗАЦИЯ** очищает `ReservedCpuSets`, если панель доступна. Чтобы сохранить собственную маску резервирования вместе с настройками устройств, применяйте изменения вручную через **ПРИМЕНИТЬ**.

Подробнее: *Windows Internals*, 7-е изд., ч. 1, с. 278–283, и [документация CPU Sets](https://learn.microsoft.com/en-us/windows/win32/procthread/cpu-sets).

## Проверка выбора

Сверьте отмеченные логические CPU с физическими ядрами и CCD/CCX. После перезагрузки проверьте фактическое размещение потоков и обработчиков прерываний по трассе ETW ([глава 10](./10-verification.ru.md#просмотр-трассы)).
