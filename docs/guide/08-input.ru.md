# Ввод: Polling Rate, Raw Input и Mouse Throttle

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 08 · [English](./08-input.md)

## Путь от USB-опроса до цикла игры

Отчёт USB-мыши проходит несколько уровней, прежде чем игра отреагирует на движение:

```text
USB polling → xHCI ISR/DPC → стек ввода ядра Windows (win32k / Raw Input) → очередь сообщений окна
```

Частота опроса USB определяет, как часто хост-контроллер xHCI запрашивает данные у мыши; затем подсистема ввода складывает события Raw Input в очередь получателя, а игра забирает их по своему расписанию или в выделенном потоке ввода ([Raw Input overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)).

DEVICE TWEAKER показывает доступные сведения об опросе и измеряет фактическую частоту событий мыши в отдельном фоновом потоке Raw Input (`WM_INPUT`). Во время замера непрерывно двигайте мышью — счётчик показывает поток событий, реально дошедший до приложения. Нажатия клавиш слишком редки, чтобы аналогично оценивать polling rate клавиатуры.

## Поштучное чтение против `GetRawInputBuffer`

На 4000–8000 Гц чтение сообщений `WM_INPUT` по одному в основном потоке игры создаёт тяжёлую нагрузку на очередь сообщений и заметно снижает FPS. Игры решают это либо выделенным потоком ввода, либо пакетным разбором накопленных событий через [GetRawInputBuffer](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getrawinputbuffer). Такая буферизация работает уже внутри приложения при чтении пришедших событий — в отличие от USB IMOD, она не задерживает аппаратные прерывания на контроллере.

Всегда проверяйте высокие частоты опроса в конкретной игре, оценивая одновременно стабильность времени кадра и отклик: далеко не каждый движок чисто переваривает 4–8 кГц.

## Mouse Throttle

Начиная с предварительного обновления Windows 11 22H2 KB5027303 (сборка `22621.1928`, массово вошло в июльское обновление KB5028185), в системе появилось [ограничение частоты Raw Input для фоновых окон](https://support.microsoft.com/en-us/servicing/os/windows-11/2023/06/june-27-2023-kb5027303-os-build-22621-1928-preview), чтобы оверлеи, софт периферии и фоновые утилиты не сжигали CPU на мышах 4–8 кГц. Интервал задаётся параметром:

```text
HKCU\Control Panel\Mouse
  RawMouseThrottleDuration  REG_DWORD
```

Как Windows обрабатывает этот параметр:

- **Только фоновые получатели:** на активное окно в фокусе (игру) ограничение не действует; геймпады и контроллеры также идут мимо этого механизма.
- **Значение по умолчанию и допустимый диапазон:** без пользовательского параметра Windows использует **8 мс (≈125 Гц)**, а `win32kbase.sys` принимает значения **1–20 мс (`0x1–0x14`)** (значения вне диапазона игнорируются). В DEVICE TWEAKER доступны пресеты `1, 2, 4, 5, 8, 10` и `20 мс` с расчётной подписью `1000 / интервал` Гц. Поскольку фактическая частота зависит от таймеров Windows и того, как фоновое приложение разбирает очередь сообщений, проверяйте реальную доставку в целевом приложении — особенно на `1` и `2 мс`.
- **Выключение и AUTO:** выключение тумблера удаляет `RawMouseThrottleDuration` и возвращает штатное поведение Windows. **АВТООПТИМИЗАЦИЯ** ставит **20 мс (≈50 Гц)** — максимальное ограничение фоновых получателей ради минимальной нагрузки в фоне во время игры. Если вы пользуетесь фоновыми оверлеями, захватом или макросами, которым нужна высокая частота мыши без фокуса, проверьте их работу или выберите меньший интервал.

Выберите интервал и нажмите **ПРИМЕНИТЬ**, чтобы сохранить его после создания бэкапа; при ошибке записи правка остаётся неприменённой.
