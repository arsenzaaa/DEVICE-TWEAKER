# USB-контроллеры и IMOD

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 05 · [English](./05-usb-imod.md)

## Контроллер и interrupter

xHCI-контроллер обслуживает устройства, подключённые к его USB-портам. У его interrupter есть собственные Event Ring и регистры IMOD. Несколько устройств могут использовать один interrupter, поэтому при разных значениях для мыши, клавиатуры и аудио важна карта привязок.

IMOD задаёт минимальный интервал между прерываниями одного interrupter с шагом 250 нс. Значение `0x0` снимает это ограничение. DEVICE TWEAKER показывает `0xC8` (50 мкс) как базовый интервал. В разделе 5.5.2.2 [спецификации xHCI](https://www.intel.com/content/dam/www/public/us/en/documents/technical-specifications/extensible-host-controler-interface-usb-xhci.pdf) указано значение регистра по умолчанию `0xFA0` (1 мс). Чтобы узнать текущий интервал после запуска драйвера, считайте регистр.

## Выбор режима

**XHCI** задаёт одно значение для всех interrupter контроллера. В режиме **Устройства** доступны отдельные поля для распознанных ролей мыши, клавиатуры, геймпада и аудио. Программа сопоставляет роли с interrupter. Если надёжной карты нет, используется общее значение контроллера. **Interrupters** открывает ручную настройку по индексам.

Если несколько настроенных ролей делят один interrupter, программа выбирает значение по приоритету ролей: мышь, клавиатура, аудио, геймпад, веб-камера. Например, если мышь и USB-аудио делят interrupter, для него используется значение мыши.

Перед редактированием нажмите **ПРОВЕРИТЬ**. В подробностях видны привязки устройств и значения регистров для первых 64 interrupter. После переподключения устройства, выхода из сна или перезагрузки считайте карту заново, поскольку привязки могли измениться. В подсказке текущего значения указано время последнего чтения.

В [галерее](../SCREENSHOTS.ru.md#контроллер-usb) показана целая карточка USB-контроллера в режиме XHCI.

## Применение и сохранение

Введите значения для выбранного режима и нажмите **ЗАДАТЬ** в карточке контроллера. Программа создаст бэкап и запишет регистры этого контроллера. После успешной записи пользовательские значения сохраняются для автозапуска. При ошибке или частичной записи остаётся прежний профиль. Если регистры записаны частично или профиль не сохранился, откройте **ПОДРОБНОСТИ**.

При ошибке в поле роли команды **ЗАДАТЬ** и **ПРИМЕНИТЬ** останавливаются и указывают, какое поле исправить.

[Задача автозапуска](./11-driver.ru.md#сохранённый-профиль) повторно применяет профиль при входе в Windows, после пробуждения и при соответствующих событиях USB/HID.

В окне АВТООПТИМИЗАЦИИ **ПРОПУСТИТЬ** оставляет текущий профиль USB IMOD и NIC ITR без изменений. При выборе **ПРИМЕНИТЬ** новые настройки USB сохраняются после успешной записи.

AUTO предлагает `0x0` для найденной мыши, `0xC8` для клавиатуры, геймпада или веб-камеры и `0xFA0` для USB-аудио. При меньшей модерации контроллер может чаще прерывать CPU. Сравните частоту прерываний и работу ввода или звука под одной и той же нагрузкой.

## Удаление и восстановление

**УДАЛИТЬ ПРОФИЛЬ** после подтверждения создаёт бэкап и удаляет общий профиль автозапуска USB IMOD и NIC ITR. Для обнаруженных адаптеров из профиля программа возвращает значения по умолчанию из INF драйвера, если параметры модерации по-прежнему выключены. Если в INF драйвера не указано подходящее значение по умолчанию, параметр остаётся прежним.

Если восстановить сетевую модерацию не удалось, задача автозапуска удаляется, а профиль остаётся для повторной попытки. Проверьте адаптер, указанный в логе, и снова нажмите **УДАЛИТЬ ПРОФИЛЬ**.

Перезагрузите Windows, чтобы сбросить действующие значения регистров. Команда также удаляет подготовленный файл `DTIMOD.sys`, если он соответствует этой сборке и больше не используется. Если DTIMOD был загружен, повторите команду после перезагрузки, чтобы удалить файл.
