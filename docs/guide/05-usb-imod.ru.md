# USB-контроллеры и IMOD

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 05 · [English](./05-usb-imod.md)

## Interrupter'ы xHCI и как работает IMOD

У отдельного USB-устройства нет собственного вектора MSI/MSI-X: все векторы и прерывания принадлежат PCIe-контроллеру **xHCI**. Цепочка доставки события выглядит так:

```text
USB-устройство → Endpoint (Device Slot) → Transfer Event → Event Ring → Interrupter (IMOD) → вектор MSI/MSI-X → CPU
```

У каждого interrupter есть свой Event Ring и MMIO-регистр **IMOD** (`Runtime Base + 0x20 + 0x20 × i + 0x04`). В зависимости от контроллера, драйвера и порядка инициализации несколько устройств могут делить один и тот же interrupter, поэтому для раздельных настроек мыши, клавиатуры и USB-аудио важно знать фактическую карту привязок.

IMOD задаёт минимальный интервал между соседними прерываниями одного interrupter с шагом **250 нс**:

- **`0xFA0`** (`4000 × 250 нс = 1 мс`): аппаратное значение по умолчанию из раздела 5.5.2.2 [спецификации xHCI](https://www.intel.com/content/dam/www/public/us/en/documents/technical-specifications/extensible-host-controler-interface-usb-xhci.pdf).
- **`0xC8`** (`200 × 250 нс = 50 мкс`): рабочее значение, которое драйвер Windows `usbxhci.sys` обычно записывает при инициализации контроллера на Windows 8/10/11 (в DEVICE TWEAKER оно указано как базовый ориентир). Чтобы увидеть реальное значение после запуска драйвера, считайте регистры контроллера.
- **`0x0`**: полное отключение модерации прерываний.

Практический эффект напрямую зависит от частоты опроса и типа устройства. На 1000 Гц (интервал 1000 мкс) штатные 50 мкс невелики; а на **4000–8000 Гц** (период 250–125 мкс) окно в 50 мкс составляет уже 20–40% периода опроса и может давать заметный джиттер (при `0xFA0` / 1 мс 8 кГц вообще захлёбывается). Для **USB-аудио** или второстепенных контроллеров логика обратная: повышенный IMOD (`0xFA0` и выше, пока нет щелчков и выпадений звука) снижает частоту прерываний и нагрузку на CPU. Снижение IMOD всегда обменивает задержку буферизации на рост числа прерываний. Оценивайте результат на своём железе, не ожидая одинакового выигрыша на всех устройствах.

## Выбор режима

- **XHCI:** одно общее значение IMOD для всех interrupter контроллера.
- **Устройства:** раздельные значения по распознанным ролям (мышь, клавиатура, геймпад, аудио, веб-камера) на основе декодированной карты контекстов xHCI; если надёжную карту получить не удалось, применяется общее значение контроллера. Когда несколько настроенных ролей делят один interrupter, выбирается роль с более высоким приоритетом: **Мышь → Клавиатура → Аудио → Геймпад → Веб-камера**.
- **Interrupters:** ручной ввод значений по индексам interrupter.

Перед редактированием нажмите **ПРОВЕРИТЬ**, чтобы считать текущие регистры и раскрыть таблицу подробностей (до 64 interrupter). Поскольку индексы Device Slot и interrupter могут меняться после переподключения периферии, сна или перезагрузки, перечитывайте карту при изменении состава USB-устройств. Время последнего чтения видно во всплывающей подсказке текущего значения.

Целая карточка USB-контроллера в режиме XHCI показана в [галерее](../SCREENSHOTS.ru.md#контроллер-usb).

## Применение и сохранение

Введите значения и нажмите **ЗАДАТЬ** в карточке контроллера. Программа создаст бэкап, запишет регистры выбранного контроллера, раскроет таблицу обратного чтения и сохранит пользовательские значения в профиль автозапуска после успешной записи. При сбое или частичной записи прежний профиль сохраняется; подробности шага ошибки доступны по кнопке **ПОДРОБНОСТИ**. Некорректное значение в любом поле роли останавливает **ЗАДАТЬ** и **ПРИМЕНИТЬ** до начала записи.

Поскольку аппаратные регистры сбрасываются при перезагрузке, выходе из сна и реинициализации контроллера, [задача автозапуска](./11-driver.ru.md#сохранённый-профиль) повторно применяет профиль при входе в систему, пробуждении и соответствующих событиях USB/HID.

В окне **АВТООПТИМИЗАЦИИ** кнопка **ПРОПУСТИТЬ** оставляет текущий профиль USB IMOD и NIC ITR без изменений, а **ПРИМЕНИТЬ** задаёт `0x0` для обнаруженной мыши, `0xC8` для клавиатуры, геймпада или веб-камеры и `0xFA0` для USB-аудио, сохраняя профиль после успешной записи.

## Удаление и восстановление

**УДАЛИТЬ ПРОФИЛЬ** после подтверждения создаёт бэкап и удаляет общий профиль автозапуска USB IMOD и NIC ITR. Для сетевых адаптеров из этого профиля программа также возвращает значения по умолчанию из INF драйвера для поддерживаемых параметров модерации, которые оставались в состоянии **Выкл** (если подходящего значения в INF нет, параметр не меняется).

Если восстановить сетевую модерацию не удалось, задача автозапуска удаляется, а файл профиля остаётся для повторной попытки: проверьте адаптер в логе и снова нажмите **УДАЛИТЬ ПРОФИЛЬ**.

Чтобы сбросить действующие значения регистров MMIO, перезагрузите Windows. Команда также удаляет подготовленный файл `DTIMOD.sys`, если он совпадает с этой сборкой и не занят; если драйвер ещё загружен в память, повторите команду после перезагрузки.
