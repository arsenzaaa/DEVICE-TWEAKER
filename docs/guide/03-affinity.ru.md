# Affinity, политики и приоритет прерываний

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 03 · [English](./03-affinity.md)

## Выбор CPU

Interrupt Affinity задаёт логические CPU, на которых могут обслуживаться прерывания устройства. Перенос этой работы с занятого игрового ядра может уменьшить конкуренцию за процессорное время. Начните с конкретного устройства и нагрузки, затем сравните результат с исходной конфигурацией.

Ориентируйтесь на подписи в списке CPU: два SMT-соседа делят одно физическое ядро. У гибридного процессора различайте P- и E-ядра, у процессора с несколькими CCD проверьте, что выбранные ядра находятся на нужном CCD. Подписи разобраны в [главе 7](./07-cpu-topology.ru.md).

Для ручной привязки отметьте нужные CPU и используйте **SpecCPU**. Нажмите **ПРИМЕНИТЬ**, чтобы сохранить политику и маску, затем перезагрузите Windows. AUTO подбирает ядра по обнаруженной топологии. У [GPU](./04-gpu.ru.md) и [сетевых адаптеров](./06-network.ru.md) есть свои правила распределения.

## Политики

**SpecCPU** использует выбранные в карточке CPU. **MachineDefault** возвращает управление выбором процессоров Windows. В карточке с ручной привязкой IRQ выберите **MachineDefault** и нажмите **ПРИМЕНИТЬ**, чтобы снять ручную привязку. В карточке NDIS выберите **RSS**, **IRQ** или **BOTH** в настройках сети.

Выберите одну из следующих политик, чтобы процессоры выбирала Windows. При выборе такой политики карточка снимает ручные отметки CPU:

- **AllClose** использует процессоры, близкие к устройству в топологии NUMA. На системе без NUMA работает как **All**.
- **Single** запрашивает один близкий процессор; на системе без NUMA Windows может выбрать любой.
- **All** допускает распределение прерываний между процессорами системы.
- **SpreadMessages** запрашивает распределение разных сообщений между процессорами, когда это возможно. Используются сообщения, выделенные устройству и драйверу.

Политики Windows описаны в *Windows Internals*, 7-е изд., ч. 2, с. 52–54, и в [справочнике IRQ_DEVICE_POLICY](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_device_policy).

## Маска affinity

Программа рассчитывает маску по отмеченным CPU. Бит N соответствует логическому CPU N в группе процессоров 0. Поддерживается до 64 логических процессоров. Например, CPU 8 и 9 дают `0x300`.

Значения сохраняются в ветке реестра устройства:

```text
Device Parameters\Interrupt Management\Affinity Policy
  DevicePolicy           REG_DWORD
  AssignmentSetOverride  REG_BINARY
  DevicePriority         REG_DWORD
```

В `AssignmentSetOverride` этот пример хранится как `00 03 00 00 00 00 00 00`, в порядке little-endian. Формат описан в [документации по Interrupt affinity](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/interrupt-affinity-and-priority).

## IRQ Priority

**Undefined**, **Low**, **Normal** и **High** задают предпочтение для обслуживания прерываний. Windows учитывает это предпочтение при назначении IRQL исходя из платформы и ресурсов устройства. AUTO выставляет **High** для устройств, которым подбирает CPU. Для встроенной графики и других исключённых устройств может использоваться **Undefined**. Для аудио через видеокарту AUTO сохраняет прежний приоритет. Подробнее в [справочнике IRQ_PRIORITY](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_priority).

## Проверка результата

После перезагрузки сверьте политику и маску с логом. На трассе сопоставьте выполнение ISR и DPC нужного драйвера с занятыми потоками приложения. Например, если при исходных настройках обработчики часто выполняются на CPU 0 вместе с игровым потоком, проверьте, уменьшилась ли конкуренция после изменения привязки и как изменилось время кадра. См. [проверку результата](./10-verification.ru.md).

Для контроллеров накопителей CPU выбирают Windows и драйвер. В карточке накопителя доступны настройки MSI и IRQ Priority.
