# Affinity, политики и приоритет прерываний

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 03 · [English](./03-affinity.md)

## Зачем управлять привязкой прерываний

По умолчанию заметная часть системных таймеров (clock owner на CPU 0), прерываний и DPC оседает на первых ядрах, а механизм **Interrupt Steering** может динамически перекидывать перенаправляемые прерывания с запаркованных ядер (*Windows Internals*, 7-е изд., ч. 2, гл. 8). Перенос активных устройств (GPU, xHCI, аудио, проводная сеть) на отдельные физические ядра снижает прямое вытеснение рабочих потоков приложения на уровне IRQL.

При ручном выборе ядер учитывайте топологию в списке CPU:

- **SMT-соседи** делят исполнительные блоки и кэш L1/L2 одного физического ядра, поэтому переносить шумное устройство на второй поток занятого игрового ядра бессмысленно.
- На **гибридных CPU** различайте P-ядра и E-ядра.
- На **многочиплетных CPU (multi-CCD)** разные CCD не имеют общего кэша L3; держите связанные назначения в пределах нужного CCD.

Как читать подписи топологии, описано в [главе 7](./07-cpu-topology.ru.md). Для ручной привязки отметьте нужные CPU, выберите **SpecCPU**, нажмите **ПРИМЕНИТЬ** и перезагрузите Windows. AUTO использует встроенные правила под обнаруженную топологию; для [GPU](./04-gpu.ru.md) и [сетевых адаптеров](./06-network.ru.md) применяются отдельные схемы.

## Политики (`IRQ_DEVICE_POLICY`)

- **SpecCPU** (`IrqPolicySpecifiedProcessors`, значение `4`): жёстко ограничивает прерывания отмеченными в карточке логическими CPU.
- **MachineDefault** (`IrqPolicyMachineDefault`, значение `0`): возвращает выбор процессоров Windows. На обычных устройствах выбор **MachineDefault** (или снятие всех отметок CPU) с нажатием **ПРИМЕНИТЬ** удаляет ручную привязку. Для NDIS-адаптеров режим выбирается отдельным переключателем **RSS / IRQ / BOTH**.
- **AllClose** (`IrqPolicyAllCloseProcessors`): использует процессоры NUMA-узла устройства (на обычной системе без NUMA эквивалентно **All**).
- **Single** (`IrqPolicyOneCloseProcessor`): запрашивает один ближайший процессор; без NUMA Windows может выбрать любой.
- **All** (`IrqPolicyAllProcessorsInMachine`): допускает размещение на любом процессоре системы.
- **SpreadMessages** (`IrqPolicySpreadMessagesAcrossAllProcessors`): просит распределить разные сообщения MSI/MSI-X по разным процессорам в пределах выделенных драйверу векторов.

При выборе любой политики под управлением Windows ручные отметки CPU в карточке снимаются. См. *Windows Internals*, 7-е изд., ч. 2, с. 52–54 (табл. 8-5), и [IRQ_DEVICE_POLICY](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_device_policy).

## Маска affinity и формат в реестре

Программа собирает 64-битную маску по отмеченным логическим CPU в группе процессоров 0 (бит `N` соответствует логическому CPU `N`). Например, CPU 8 и 9 дают `0x300`.

Параметры записываются в ветку устройства:

```text
Device Parameters\Interrupt Management\Affinity Policy
  DevicePolicy           REG_DWORD
  AssignmentSetOverride  REG_BINARY
  DevicePriority         REG_DWORD
```

В `AssignmentSetOverride` маска `0x300` хранится в little-endian как `00 03 00 00 00 00 00 00` (при чтении программа также корректно разбирает короткие 1–7-байтные маски `REG_BINARY`, оставленные другими утилитами). Формат описан в [Interrupt affinity and priority](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/interrupt-affinity-and-priority).

## IRQ Priority

`DevicePriority` (**Undefined**, **Low**, **Normal**, **High**) служит подсказкой (hint) для PnP-арбитра при выборе вектора IDT и соответствующего уровня **DIRQL** на x64 (*Windows Internals*, 7-е изд., ч. 2, гл. 8, табл. 8-6):

| Значение | Целевой DIRQL (x64) |
|---|---|
| `Low` (`IrqPriorityLow`) | 3–4 |
| `Normal` / `Undefined` | 5–11 (по выделенному вектору) |
| `High` (`IrqPriorityHigh`) | 12 |

Windows не является ОС реального времени: `DevicePriority` влияет **только на уровень DIRQL (порядок вытеснения между ISR разных устройств)**. Он **не** меняет приоритет DPC (обычные DPC всегда идут на `DISPATCH_LEVEL`, IRQL 2) и не ускоряет пользовательские потоки.

AUTO выставляет **High** для устройств, которым назначает CPU, для встроенной графики и исключённых устройств может оставлять **Undefined**, а для аудио через видеокарту сохраняет исходный приоритет. См. [IRQ_PRIORITY](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_priority).

## Накопители и проверка результата

Для контроллеров NVMe и SATA многопоточное распределение очередей контролируют Windows и драйвер-минипорт (`stornvme` / `storport`), поэтому в их карточках доступны только MSI и IRQ Priority.

После перезагрузки сверьте сохранённую маску с логом и проверьте трассу ETW под нагрузкой: действительно ли ISR и DPC нужного драйвера ушли с занятого ядра (например, с CPU 0) и как это отразилось на времени кадра. Подробная методика описана в [главе 10](./10-verification.ru.md).
