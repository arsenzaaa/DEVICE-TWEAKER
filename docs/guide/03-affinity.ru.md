# Affinity, политики и приоритет прерываний

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 03 · [English](./03-affinity.md)

## Выбор CPU

Interrupt Affinity задаёт логические CPU, на которых могут обслуживаться прерывания устройства. Перенос этой работы с занятого игрового ядра может уменьшить конкуренцию за процессорное время. Начните с конкретного устройства и нагрузки, затем сравните результат с исходной конфигурацией.

Ориентируйтесь на подписи в списке CPU: два SMT-соседа делят одно физическое ядро. У гибридного процессора различайте P- и E-ядра, у процессора с несколькими CCD смотрите расположение выбранных ядер. Подписи разобраны в [главе 7](./07-cpu-topology.ru.md).

Для ручной привязки отметьте нужные CPU и используйте **SpecCPU**. Нажмите **ПРИМЕНИТЬ**, чтобы сохранить политику и маску, затем перезагрузите Windows. AUTO подбирает ядра по обнаруженной топологии; у [GPU](./04-gpu.ru.md) и [сетевых адаптеров](./06-network.ru.md) есть свои правила распределения.

## Политики

**SpecCPU** использует выбранные в карточке CPU. **MachineDefault** возвращает выбор процессоров Windows. Если снять все отметки у обычного устройства и применить настройки, его пользовательская привязка удаляется. Для сетевых карточек предусмотрены отдельные режимы RSS/IRQ.

Остальные политики поручают Windows выбрать процессоры по определённому правилу:

- **AllClose** использует процессоры, близкие к устройству в топологии NUMA. На системе без NUMA работает как **All**.
- **Single** запрашивает один близкий процессор; на системе без NUMA Windows может выбрать любой.
- **All** допускает распределение прерываний между процессорами системы.
- **SpreadMessages** запрашивает распределение разных сообщений между процессорами, когда это возможно. Используются сообщения, выделенные устройству и драйверу.

Определения политик Windows приведены в [IRQ_DEVICE_POLICY](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_device_policy).

## Маска affinity

Программа рассчитывает маску по отмеченным CPU. Бит N соответствует логическому CPU N в группе процессоров 0; поддерживается до 64 логических процессоров. Например, CPU 8 и 9 дают `0x300`.

Значения сохраняются в ветке реестра устройства:

```text
Device Parameters\Interrupt Management\Affinity Policy
  DevicePolicy           REG_DWORD
  AssignmentSetOverride  REG_BINARY
  DevicePriority         REG_DWORD
```

В `AssignmentSetOverride` этот пример хранится как `00 03 00 00 00 00 00 00`, в порядке little-endian. Формат описан в [документации Interrupt affinity](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/interrupt-affinity-and-priority).

## IRQ Priority

**Undefined**, **Low**, **Normal** и **High** задают предпочтение для обслуживания прерываний. Windows учитывает его при назначении IRQL с учётом платформы и ресурсов устройства. AUTO использует **High** для настраиваемых устройств. Параметр не меняет приоритет потока игры или очереди DPC. Подробнее: [IRQ_PRIORITY](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_priority).

## Проверка результата

После перезагрузки сверьте сохранённые политику и маску с логом. ETW-трасса покажет, где действительно выполняются ISR, DPC и рабочие потоки драйвера: их целевые CPU могут различаться. Порядок проверки описан в [главе 10](./10-verification.ru.md).

Если результат отличается от ожидаемого, сначала проверьте экземпляр устройства, выбранные CPU и текущий IRQ Mode. Маска из двух CPU разрешает использовать оба, но не требует равномерной загрузки.

Для накопителей AUTO оставляет affinity на усмотрение Windows. При ручной настройке сохраните бэкап для восстановления и проверьте загрузку системы, ввод-вывод и стабильность.
