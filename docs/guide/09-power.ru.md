# Энергосбережение устройств

[Документация](../README.ru.md) / [Руководство](./README.ru.md) / 09 · [English](./09-power.md)

## Что меняется

Power Saving управляет доступными механизмами питания устройства. USB selective suspend позволяет приостанавливать отдельные простаивающие порты. Microsoft рекомендует сохранять этот механизм; конкретные драйверы и классы устройств имеют свои ограничения. См. [USB selective suspend](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-selective-suspend) и [особенности HID](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/selective-suspend-for-hid-over-usb-devices).

AUTO отключает энергосбережение у настраиваемых устройств. Перед сохранением изменения сравните отклик, энергопотребление, сон и пробуждение на своей системе.

## USB и проводная сеть

Для USB программа работает с контроллером и связанными корневыми хабами, доступными параметрами Device Parameters, PnPCapabilities и WMI. Общая настройка USB selective suspend в плане питания применяется отдельно от настройки устройства.

Для поддерживаемого проводного адаптера меняется разрешение Windows отключать устройство. PnPCapabilities обрабатывается как набор битов с сохранением остальных признаков; одно число нельзя объявлять универсальным значением для всех драйверов. Wi-Fi исключён из автоматических изменений.

## Подтверждение результата

Значение в реестре, состояние WMI и фактическое поведение устройства - разные уровни проверки. Неподдерживаемый WMI-параметр, ошибка записи и несовпадение readback должны оцениваться раздельно. Галочка в карточке сама по себе не подтверждает живую политику питания.

После изменения проверьте длительную работу, простой, сон и пробуждение. Если устройство начинает пропадать или хуже просыпаться, восстановите исходные настройки.

## Восстановление

Восстановление использует значения выбранной копии, а не текущие галочки UI. USB selective suspend восстанавливается через Windows Power API для AC/DC и проверяется чтением; текущая схема питания не заменяется другой. Ошибка живого применения остаётся частичным результатом, даже если реестр уже восстановлен.
