## Интерфейс

Тумблеры, прокрутка и подсветка кнопок используют короткие плавные переходы. Анимации работают независимо от визуальных эффектов Windows. При высокой контрастности переходы выполняются мгновенно.

Язык интерфейса сохраняется в `%LOCALAPPDATA%\DEVICE TWEAKER\settings.json`.

## Прерывания

### MSI / MSI-X

**MSI Mode** задаёт сохраняемый режим прерываний. Выбор в списке сначала остаётся правкой; **ПРИМЕНИТЬ** записывает `MSISupported` в реестр устройства. Перезагрузите Windows, чтобы проверить, использует ли драйвер новую настройку. Если PCI явно сообщает о поддержке сообщений без линейных прерываний INTx, программа отклоняет отключение MSI.

**IRQ Mode** показывает текущий режим: Line, MSI, MSI-X или MSI/MSI-X, когда данных для различения двух режимов сообщений недостаточно. Сочетание сохранённого **Включено** и текущего **Line** может означать, что нужна перезагрузка или драйвер устройства не использовал настройку. Различие разобрано в [главе 2](./guide/02-msi.ru.md).

**СЧИТАТЬ IRQ** проверяет все PCI-устройства списка, включая скрытые фильтром карточки. Программа читает выделенные Windows ресурсы прерываний, а через DTIMOD - биты PCI `MSI Enable` / `MSI-X Enable`. Эти биты позволяют различить MSI и MSI-X даже при одном IRQ. Команда может загрузить DTIMOD, но не применяет настройки. Ход чтения и итоговое количество считанных устройств показаны на кнопке, сводка - в её подсказке.

При открытии программы и нажатии **ОБНОВИТЬ** также начинаются фоновые чтения через ресурсы Windows или уже загруженный DTIMOD. Они не загружают драйвер. Перед чтением старый результат очищается; недоступные данные, ошибки и противоречия показываются отдельно и записываются в лог. **Нет IRQ** означает отсутствие выделенных ресурсов прерываний. Успешное чтение относится к моменту проверки: [маршрутизация MSI-X может меняться во время работы](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/dynamically-configuring-msi-x).

**HW** перечисляет поддерживаемые устройством режимы прерываний и максимум сообщений. **IRQ** показывает количество выделенных ему ресурсов прерываний Windows.

**MSI Limit** задаёт `MessageNumberLimit`. **Unlimited** удаляет пользовательский лимит из реестра, оставляя выбор Windows и драйверу. Введённое число проверяется по обнаруженным возможностям устройства. Подробнее: [включение MSI](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/enabling-message-signaled-interrupts-in-the-registry).

**IRQ Priority** записывает `DevicePriority` - предпочтительный приоритет аппаратного прерывания для Windows. Значения и работа политик описаны в [главе об affinity](./guide/03-affinity.ru.md#irq-priority).

### Interrupt Affinity

**[Interrupt Affinity](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/interrupt-affinity-and-priority)** задаёт логические процессоры, допустимые для IRQ устройства. В выборе видны SMT/HT-потоки, Intel P/E-cores, AMD CCD/CCX и доступный CPPC-рейтинг. Это позволяет выбирать не просто номера CPU, а конкретные физические ядра и их соседние потоки.

Режим **SpecCPU** записывает `DevicePolicy` и `AssignmentSetOverride`. Если снять выбор CPU у обычного устройства, программа записывает `DevicePolicy=0` (`MachineDefault`) и удаляет `AssignmentSetOverride`; для сетевых адаптеров NDIS действует выбранный режим RSS/IRQ.

Маска охватывает группу процессоров 0, до 64 логических CPU. Выбор процессоров описан в [главе 3](./guide/03-affinity.ru.md), трассировка ISR/DPC - в [главе 10](./guide/10-verification.ru.md).

В **Policy** доступны `MachineDefault`, `All`, `AllClose`, `Single`, `SpecCPU` и [`SpreadMessages`](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ne-wdm-_irq_device_policy). Только `SpecCPU` использует отмеченную в списке маску. Остальные политики передают выбор процессоров Windows; `SpreadMessages` может распределять разные сообщения по разным CPU, если устройство и драйвер используют несколько MSI-X-векторов. Сама политика не создаёт дополнительные векторы.

## USB xHCI IMOD

USB IMOD использует DTIMOD. Программа запрашивает подтверждение один раз за запуск; в AUTO оно включено в вопрос об USB IMOD. **О ДРАЙВЕРЕ** показывает HVCI, параметр списка блокировки драйверов в реестре и состояния служб FACEIT/Vanguard. Загрузка и совместимость описаны в [главе о драйвере](./guide/11-driver.ru.md).

AUTO задаёт для мыши IMOD `0x0`, отключая модерацию независимо от polling rate. Ручные значения настраиваются отдельно.

**[IMOD](https://cdrdv2-public.intel.com/625472/625472_xHCI_Rev1_2b.pdf)** задаёт интервал модерации прерываний xHCI. Регистр принадлежит *interrupter* контроллера с собственным Event Ring, а не отдельной мыши или клавиатуре. Один шаг равен 250 нс. Значение `0xC8` задаёт 50 мкс, `0xFA0` задаёт 1 мс, `0x0` отключает модерацию.

Режим **Устройства** составляет профиль для обнаруженных мышей, клавиатур, геймпадов и USB-аудио и пытается сопоставить их с interrupter по топологии xHCI. При отсутствии надёжной карты применяется общее значение для контроллера. **XHCI** записывает одно значение во все interrupter, **Interrupters** открывает настройку по индексам. В подробностях показываются значения IMOD для первых 64 interrupter.

В подсказке текущего значения указано время последнего чтения. После подключения или отключения устройства карта помечается "устройства изменились"; **ПРОВЕРИТЬ** читает её заново.

### Команды

- **ЗАДАТЬ** записывает выбранную конфигурацию, затем перечитывает регистры. Свои значения программа сохраняет в автозапуск (см. ниже).
- **ПРОВЕРИТЬ** заново считывает регистры и при необходимости загружает DTIMOD. **ОБНОВИТЬ** обновляет список устройств и доступное текущее состояние; аппаратное чтение использует уже загруженный DTIMOD.
- **УДАЛИТЬ** убирает общий автозапуск IMOD и сохранённых профилей NIC ITR и возвращает модерацию драйвера сетевой карты, выключенную через **СОХРАНИТЬ**. В интерфейсе выставляется базовое значение IMOD `0xC8`. Запись в регистры возможна только при уже загруженном DTIMOD и пропускается, если в конфигурации остались только записи NIC ITR. Для завершения сброса перезагрузите Windows.

Перед **УДАЛИТЬ** отдельный автоматический бекап не создаётся.

Общая кнопка **ПРИМЕНИТЬ** также применяет настройки USB IMOD вместе с остальными настройками устройств.

Привязки interrupter, интервалы модерации и профили ролей устройств разобраны в [главе USB](./guide/05-usb-imod.ru.md).

### Автозапуск IMOD / NIC ITR

Сохранённый профиль находится в `%ProgramData%\DEVICE TWEAKER\Startup`. Задача `\DEVICE TWEAKER\IMOD` работает от SYSTEM при входе, после пробуждения и при соответствующих событиях USB/HID. Настройки применяются независимо от EXE. Прежний автозапуск AppData/Run переносится с сохранением значений.

Файлы, проверки хешей, права доступа и логи описаны в [главе о драйвере](./guide/11-driver.ru.md#сохранённый-профиль).

## Сетевые адаптеры

### RSS

**[RSS](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/introduction-to-receive-side-scaling)** распределяет обработку входящих пакетов по CPU с помощью хеша и таблицы перенаправления. **RSS Queues** задаёт запрашиваемое число приёмных очередей, базовый CPU служит отправной точкой для выбора процессоров. **NDIS Mode** позволяет применить RSS, Interrupt Affinity или оба параметра.

Выбор очередей учитывает варианты, объявленные драйвером адаптера. Для RSS берётся один логический процессор на физическое ядро; `*MaxRssProcessors` и `*RssMaxProcNumber` задают запрашиваемый диапазон. У адаптеров без MSI-X несколько объявленных очередей могут обслуживаться одним процессором. AUTO запрашивает одну очередь на одном физическом ядре; наличие SMT не удваивает это число. Настройки разобраны в [главе о сети](./guide/06-network.ru.md).

Карточка показывает сохранённые параметры и активное состояние `Get-NetAdapterRss`; расхождения записываются в лог. [Профиль Balanced](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/standardized-inf-keywords-for-rss) управляет выбором процессоров автоматически. Применение записанных RSS-параметров зависит от драйвера адаптера; его перезапуск остаётся за пользователем.

### NIC ITR

**NIC ITR** работает с аппаратными регистрами модерации поддерживаемых сетевых контроллеров: Intel I210/I211, I219, I225/I226, I350, 82576/82580, Realtek RTL8111/8168, RTL8125/8126 и совместимых Killer. Для неизвестного PCI ID аппаратная запись закрыта.

**ЗАДАТЬ** записывает регистр сейчас, **СОХРАНИТЬ** записывает профиль в автозапуск, не меняя текущий регистр; **ПРОВЕРИТЬ** перечитывает аппаратное состояние.

Собственная адаптивная модерация драйвера перезаписала бы значение в регистре, поэтому **СОХРАНИТЬ** выключает её в реестре (`*InterruptModeration`, у Intel также `ITR`). Изменение вступает в силу после перезагрузки. Текущее состояние видно в строке **Interrupt Moderation** карточки; **УДАЛИТЬ** в блоке IMOD возвращает значение драйвера по умолчанию. Формат регистра и единицы интервала зависят от семейства контроллера: число из [EITR Intel](https://cdrdv2-public.intel.com/333016/333016%20-%20I210_Datasheet_v_3_7.pdf) не является готовым профилем Realtek. Более короткий интервал может увеличить число прерываний и нагрузку на CPU.

## Дополнительные настройки

**ReservedCpuSets** задаёт системную маску резервирования CPU. Выбор процессоров и формат значения описаны в [главе о CPU](./guide/07-cpu-topology.ru.md#reservedcpusets).

**Power Saving** управляет доступными настройками энергосбережения USB-контроллера и связанных с ним корневых USB-хабов, включая [USB selective suspend](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-selective-suspend). Для проводного сетевого адаптера переключатель меняет разрешение Windows отключать устройство ради экономии энергии. Фактическая доступность этих параметров зависит от драйвера.

На поддерживаемых сборках Windows 11 **Mouse Throttle** меняет `RawMouseThrottleDuration`. Этот параметр задаёт интервал ограничения для фоновых обработчиков [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/raw-input), к которым Windows применяет throttling. Некоторые фоновые регистрации могут обходить это ограничение. Настройка не меняет USB polling rate мыши и не нацелена на активное окно.

**Замер Raw Input** оценивает частоту событий движущейся мыши. Доставка событий и polling rate разобраны в [главе о вводе](./guide/08-input.ru.md).

Кнопки **МЫШЬ**, **КЛАВИАТУРА**, **ГЕЙМПАД**, **USB**, **GPU**, **СЕТЬ**, **ЗВУК** и **НАКОПИТЕЛИ** перемещают к соответствующим устройствам в общем списке. Строка поиска скрывает несовпадающие устройства.

## Интеллектуальная авто-оптимизация и восстановление

**АВТООПТИМИЗАЦИЯ** выбирает физические ядра по топологии и CPPC-рейтингу. Для системы с несколькими CCD отдельно выбирается целевой CCD; SMT-потоки одного ядра не считаются двумя независимыми ядрами. Для дискретной GPU подбираются два разных физических ядра; для встроенной GPU аффинити возвращается к выбору Windows. Для устройств ввода, проводной сети и аудио действуют свои правила совместного размещения.

Если подходящего ядра или надёжно определённой роли нет, назначение пропускается с причиной в отчёте. Если топология CPU определена ненадёжно, запись масок не начинается. Для NDIS интеллектуальная авто-оптимизация подбирает режим RSS/IRQ по обнаруженному состоянию адаптера. При запуске можно включить настройку USB IMOD, NIC ITR настраивается вручную.

Перед общим ручным применением, **ЗАДАТЬ** для IMOD / NIC ITR, **СОХРАНИТЬ** для NIC ITR, восстановлением бекапа и общим сбросом создаётся проверенная резервная копия. Для интеллектуальной авто-оптимизации обязателен снимок исходных настроек; дополнительный бекап можно создать по желанию. Если обязательный снимок не создан, запись не начинается. Выбрать сохранённый бекап можно в разделе **ВОССТАНОВЛЕНИЕ**.

При восстановлении бэкапа устаревшая запись автозапуска NIC ITR пропускается с предупреждением. Остальные поддерживаемые настройки восстанавливаются. Сохраните NIC ITR для этого адаптера заново; подробнее в [разделе NIC ITR](./guide/06-network.ru.md#nic-itr).

При общем сбросе сохраняются MSI Mode / MSI Limit и настройки Wi-Fi.
