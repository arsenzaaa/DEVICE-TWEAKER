## Интерфейс

Тумблеры, прокрутка и подсветка кнопок используют короткие плавные переходы на общем таймере кадров, который останавливается в покое. Анимации не зависят от визуальных эффектов Windows, а в режиме высокой контрастности переходы выполняются мгновенно.

Язык интерфейса сохраняется в `%LOCALAPPDATA%\DEVICE TWEAKER\settings.json`.

## Прерывания

### MSI / MSI-X

Выберите значение **MSI Mode** и нажмите **ПРИМЕНИТЬ**, чтобы записать `MSISupported` в ветку устройства, затем перезагрузите Windows перед проверкой. Если возможности PCI явно указывают на поддержку сообщений без линейных прерываний INTx, отключение MSI блокируется.

**Режим IRQ** показывает `Line`, `MSI` или `MSI-X` (либо `MSI/MSI-X`, если ресурсы Windows подтверждают прерывания по сообщениям, но биты конфигурации PCI ещё не считаны). См. [MSI и MSI-X](./guide/02-msi.ru.md).

**СЧИТАТЬ IRQ** опрашивает все PCI-устройства списка, включая скрытые фильтром карточки, объединяя выделенные ресурсы прерываний Windows с битами PCI `MSI Enable` и `MSI-X Enable` через DTIMOD — это позволяет отличить MSI от MSI-X даже при одном IRQ. Команда может загрузить DTIMOD, ничего не меняет в настройках, показывает ход проверки и число полученных результатов на кнопке, а недоступные выводит в подсказке.

При запуске и нажатии **ОБНОВИТЬ** фоновое чтение использует ресурсы Windows и уже загруженный DTIMOD, не загружая драйвер самостоятельно. Прежний результат очищается перед чтением, а карточка и лог отдельно различают недоступные данные, ошибки и противоречия. **Нет IRQ** означает отсутствие выделенных ресурсов прерываний. Показания отражают момент проверки, так как [маршрутизация MSI-X может меняться во время работы](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/dynamically-configuring-msi-x).

**HW** показывает аппаратные режимы прерываний PCI и максимальное число сообщений, **IRQ** — число ресурсов прерываний по данным WMI. Заданный лимит отображается отдельно в **MSI Limit**.

**MSI Limit** задаёт `MessageNumberLimit`. **Unlimited** удаляет пользовательский лимит, отдавая выбор Windows и драйверу; ручной ввод проверяется по возможностям устройства ([Enabling MSI in the registry](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/enabling-message-signaled-interrupts-in-the-registry)).

**IRQ Priority** записывает `DevicePriority` — подсказку уровня DIRQL при назначении векторов IDT (влияет только на приоритет вытеснения между ISR, не на DPC). Подробнее в [IRQ Priority](./guide/03-affinity.ru.md#irq-priority).

### Interrupt Affinity

**CPU Affinity** выбирает логические процессоры группы 0 (до 64 LP), на которых могут обслуживаться прерывания устройства. В списке показаны SMT-соседи, P-/E-ядра гибридных CPU, домены CCD/CCX и рейтинги CPPC.

**Политика** задаёт `DevicePolicy`: используйте **SpecCPU** (`4`) для отмеченной маски. На обычных устройствах снятие всех отметок с последующим **ПРИМЕНИТЬ** удаляет пользовательскую маску и возвращает **MachineDefault**. Для NDIS-адаптеров используется переключатель **RSS / IRQ / BOTH**. Все политики и формат реестра описаны в [главе 3](./guide/03-affinity.ru.md).

## USB xHCI IMOD

IMOD управляет интервалом модерации прерываний xHCI (шаг 250 нс; штатное значение Windows `usbxhci.sys` обычно `0xC8` / 50 мкс против `0xFA0` / 1 мс в спецификации xHCI) через [DTIMOD](./guide/11-driver.ru.md). Режим **XHCI** задаёт одно значение на контроллер, **Устройства** — по ролям при наличии карты контекстов, **Interrupters** — по индексам. Приоритет ролей, компромиссы по частоте опроса и значения AUTO разобраны в [главе 5](./guide/05-usb-imod.ru.md).

Время последнего чтения отображается в подсказке текущего значения. После подключения или отключения периферии карта помечается «устройства изменились» — нажмите **ПРОВЕРИТЬ**, чтобы перечитать её.

### Команды

- **ЗАДАТЬ** записывает регистры выбранного контроллера, обновляет показания, автоматически раскрывает таблицу обратного чтения по interrupter и сохраняет пользовательские значения для автозапуска после успешной записи.
- **ПРОВЕРИТЬ** считывает регистры заново (при необходимости загружая DTIMOD). **ОБНОВИТЬ** перечитывает список устройств и текущее состояние, не загружая драйвер самостоятельно.
- **УДАЛИТЬ ПРОФИЛЬ** создаёт бэкап и удаляет общий профиль автозапуска USB IMOD и NIC ITR; для сброса действующих регистров MMIO перезагрузите Windows. Восстановление сетевой модерации и удаление файла драйвера описаны в разделе [Удаление и восстановление](./guide/05-usb-imod.ru.md#удаление-и-восстановление).

Общая кнопка **ПРИМЕНИТЬ** также применяет неприменённые правки USB IMOD вместе с остальными настройками устройств.

### Автозапуск IMOD / NIC ITR

Файлы автозапуска хранятся в `%ProgramData%\DEVICE TWEAKER\Startup`. Задача `\DEVICE TWEAKER\IMOD` работает от `SYSTEM` при входе в систему, после пробуждения и по событиям USB/HID, применяя регистры независимо от EXE. Профили прежней схемы AppData/Run переносятся автоматически при сохранении настроек или восстановлении бэкапа.

Проверка хешей, права каталога и ротация логов описаны в [главе 11](./guide/11-driver.ru.md#сохранённый-профиль).

## Сетевые адаптеры

### RSS

**[RSS](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/introduction-to-receive-side-scaling)** распределяет входящие потоки пакетов по CPU через хеш и таблицу перенаправления. **Очереди RSS** задаёт запрашиваемое число приёмных очередей, базовый CPU определяет начало диапазона процессоров, а **NDIS Mode** применяет **RSS**, **IRQ** (`Affinity Policy`) или **BOTH**.

Доступные варианты очередей следуют списку драйвера, а при выборе процессоров программа берёт по одному логическому CPU на физическое ядро (без SMT-соседей). Почему AUTO выбирает минимум очередей и как очереди соотносятся с числом CPU, описано в [главе 6](./guide/06-network.ru.md#что-делает-rss).

Карточка NDIS показывает сохранённое число очередей и сводку активного RSS, а лог сверяет запрошенные параметры с текущим состоянием адаптера. При записи диапазона процессоров RSS программа выставляет `*RSSProfile = 4` (`NUMAScalingStatic`), чтобы на гибридных CPU Windows не оставалась в [профиле Balanced](https://learn.microsoft.com/en-us/windows-hardware/drivers/network/standardized-inf-keywords-for-rss), игнорирующем `*RssBaseProcNumber` и `*RssMaxProcNumber` (исходное значение сохраняется в бэкап и удаляется при сбросе). Перезагрузите Windows, чтобы драйвер применил обновлённые параметры.

Маска RSS в карточке отражает процессоры, выбранные DEVICE TWEAKER; фактический выбор адаптера проверяйте по сводке активного RSS или через `Get-NetAdapterRss`.

### NIC ITR

**NIC ITR** работает с аппаратными регистрами модерации поддерживаемых Ethernet-контроллеров: Intel I210/I211, I219, I225/I226, I350, 82576/82580, Realtek RTL8111/8168, RTL8125/8126 и совместимых Killer. Для неизвестного PCI ID аппаратная запись заблокирована.

**ЗАДАТЬ** записывает регистр сразу, **СОХРАНИТЬ** создаёт профиль автозапуска для этого экземпляра адаптера, **ПРОВЕРИТЬ** считывает текущие значения.

**СОХРАНИТЬ** отключает поддерживаемые параметры модерации драйвера (`*InterruptModeration` и применимые ключи `ITR` у Intel), чтобы адаптивная модерация не перезаписывала регистр при запуске адаптера; строка **Interrupt Moderation** показывает сохранённые значения драйвера. Команда **УДАЛИТЬ ПРОФИЛЬ** в блоке USB IMOD удаляет профиль и возвращает [применимые значения INF](./guide/05-usb-imod.ru.md#удаление-и-восстановление).

## Дополнительные настройки

**ReservedCpuSets** задаёт системную мягкую маску резервирования CPU (`REG_BINARY` в `Session Manager\Kernel`), которая ограничивает в том числе системные потоки. Подробности и предупреждение о смешивании зарезервированных и обычных ядер в одной жёсткой маске процесса — в [главе 7](./guide/07-cpu-topology.ru.md#reservedcpusets).

**Энергосбережение** управляет питанием USB-контроллера и корневых хабов (`SelectiveSuspendEnabled`, `EnhancedPowerManagementEnabled`, бит `0x08` в `PnPCapabilities`, WMI `MSPower_DeviceEnable` и глобальный [USB selective suspend](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/usb-selective-suspend)), а для проводного сетевого адаптера — разрешением отключения питания (`PnPCapabilities` / WMI), в зависимости от поддержки драйвера.

**Mouse Throttle** задаёт `HKCU\Control Panel\Mouse\RawMouseThrottleDuration` для фоновых получателей Raw Input на Windows 11 сборки `22621.1928+` (по умолчанию 8 мс, допустимый диапазон 1–20 мс; выключение удаляет пользовательское значение). Подробности и нюансы для фоновых приложений описаны в [главе 8](./guide/08-input.ru.md#mouse-throttle).

**Замер Raw Input** оценивает частоту поступающих событий движущейся мыши в отдельном фоновом потоке ([глава 8](./guide/08-input.ru.md)).

Кнопки **МЫШЬ**, **КЛАВИАТУРА**, **ГЕЙМПАД**, **USB**, **GPU**, **СЕТЬ**, **ЗВУК** и **НАКОПИТЕЛИ** переходят к соответствующим карточкам в общем списке; строка поиска скрывает несовпадающие устройства.

## Автооптимизация и восстановление

**АВТООПТИМИЗАЦИЯ** распределяет физические ядра по топологии Windows и рейтингам CPPC: на многочиплетных CPU выбирается один целевой CCD, SMT-соседи не считаются отдельными ядрами, дискретной GPU выделяется пара соседних физических ядер, встроенная графика остаётся под управлением Windows, а для ввода, проводной сети и звука действуют отдельные правила.

Устройства без подходящего ядра или надёжно распознанной роли пропускаются с причиной в отчёте; при ненадёжном определении топологии CPU маски не записываются. Для NDIS-адаптеров AUTO выбирает RSS, IRQ или BOTH по возможностям и текущему состоянию драйвера. Включать ли USB IMOD, вы выбираете перед запуском; NIC ITR настраивается вручную.

AUTO очищает [ReservedCpuSets](./guide/07-cpu-topology.ru.md#reservedcpusets), если панель резервирования доступна.

Перед ручным **ПРИМЕНИТЬ**, записью USB IMOD / NIC ITR (**ЗАДАТЬ**), сохранением NIC ITR (**СОХРАНИТЬ**), **ВОССТАНОВЛЕНИЕМ** и сбросом программа создаёт и проверяет бэкап. Для AUTO обязателен снимок исходных настроек (дополнительный бэкап можно пропустить); при сбое обязательного бэкапа запись не начинается. Выбор снимка доступен в окне **ВОССТАНОВЛЕНИЕ**.

Бэкап хранит точные пути реестра для экземпляров устройств и драйверов на момент создания — восстанавливайте его только в той же установке Windows и конфигурации железа.

При восстановлении бэкапа с устаревшей схемой регистров NIC ITR несовместимая запись автозапуска пропускается с предупреждением, а остальные поддерживаемые настройки восстанавливаются; сохраните NIC ITR для этого адаптера заново ([NIC ITR](./guide/06-network.ru.md#nic-itr)).

**СБРОС ПО УМОЛЧАНИЮ** сохраняет MSI Mode / MSI Limit и настройки Wi-Fi.
