# Выпуск DEVICE TWEAKER

[Документация](./README.ru.md) / Выпуск · [English](./RELEASE.md)

Выпуск включает два портативных EXE, контрольные суммы и точный архив исходников. Сейчас готовится замена **0.0.4** по существующему адресу. На всём протяжении замены должна сохраняться возможность восстановить прежний выпуск.

## Исходники и описание

После проверки кода, документации и истории выберите один окончательный коммит. Собирайте из чистого изолированного checkout. Поля версии в `src/DeviceTweakerCS.csproj` и `src/assets/app.manifest`, проверка пакета и резервное значение GUI должны соответствовать `0.0.4`.

Составляйте changelog 0.0.4 по сравнению **0.0.3 → окончательные исходники**, сверяя реализацию, а не копируя названия коммитов. Отдельно сохраните сравнение прежней опубликованной 0.0.4 с заменой. Для старых выпусков сравниваются соседние ревизии; 0.0.1 служит исходной точкой.

Согласуйте английский и русский changelog и описания выпусков. Сохраните исторические даты. Скрипт замены добавляет фактическую дату обновления и точный SHA исходников в опубликованное описание.

## Локальный комплект

Из **корня репозитория**, в чистом checkout:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\src\build.ps1 -Flavor both -Configuration Release -SkipImodDriverBuild
if ($LASTEXITCODE -ne 0) { throw 'Build failed' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\dev\qa\Test-ReleasePackage.ps1 -PackageDirectory .\src\bin\ReleasePackages\v0.0.4
if ($LASTEXITCODE -ne 0) { throw 'Package check failed' }

$package = '.\src\bin\ReleasePackages\v0.0.4'
$sourceName = 'DEVICE.TWEAKER.Source.v0.0.4.zip'
git archive --format=zip --output="$package/$sourceName" HEAD
if ($LASTEXITCODE -ne 0) { throw 'Source archive failed' }
$hash = (Get-FileHash -LiteralPath "$package/$sourceName" -Algorithm SHA256).Hash
"$hash  $sourceName" | Set-Content -LiteralPath "$package/SOURCE-SHA256SUMS.txt" -Encoding ascii
```

Пять файлов: `DEVICE.TWEAKER.exe`, `DEVICE.TWEAKER.SelfContained.exe`, `SHA256SUMS.txt`, `DEVICE.TWEAKER.Source.v0.0.4.zip` и `SOURCE-SHA256SUMS.txt`.

Обычному EXE нужен .NET 10 Desktop Runtime x64; автономный EXE включает среду выполнения. [Проверка пакета](../dev/qa/Test-ReleasePackage.ps1) сверяет версии, общую идентичность приложения, встроенные компоненты и отсутствие тест-панели через read-only запуск. Драйвер не загружается, аппаратные настройки не проверяются. Сверьте архив с выбранным коммитом.

Выполните связанные программные проверки, просмотрите снимки EN/RU, затем проведите аппаратную приёмку окончательных файлов. Запишите Windows, устройства, драйверы и недоступные конфигурации. Для загрузки драйвера, записи регистров и изменения настроек Windows требуется явное разрешение на тестовой системе.

## Сборка без публикации

Workflow `Release package` принимает точный 40-значный `source_sha`. По умолчанию `action=build`: восстановление зависимостей, тесты, два EXE, проверка пакета и пять файлов в Actions artifact. Права репозитория только на чтение; выпуск и тег не создаются.

Проверьте комплект, проведите приёмку этих EXE и запишите ID успешной сборки и SHA-256 файла `SHA256SUMS.txt`. Замена скачивает именно эти файлы, сверяет исходный архив с Git blobs и проверяет хеш принятого манифеста EXE. Повторной сборки при замене нет.

## Замена существующей 0.0.4

После разрешения автора на публикацию:

1. Отправьте проверенные коммиты в `main` и дождитесь CI. Выбранная ревизия должна совпадать с удалённым `main`.
2. Считайте текущий SHA `main`, **объект тега** `v0.0.4` (не только коммит после разыменования) и `updated_at` выпуска из API. До продолжения разберите отличия от сохранённого состояния. В настройках репозитория проверьте, что неизменяемость релизов отключена для замены: изменяемость старого выпуска сама по себе не подтверждает политику при повторной публикации.
3. Запустите `Release package` из `main` с `action=replace-0.0.4`, точными `source_sha`, `expected_tag_object`, `expected_release_updated_at`, `verified_run_id` и `expected_exe_sums_sha256`.
4. Отдельная задача с правом записи сохраняет метаданные, bundle старого тега/исходников и все пять файлов, сверяет SHA-256 и загружает recovery artifact **до первой удалённой записи**. Затем повторно сверяет удалённое состояние.
5. Скрипт переводит существующий выпуск в черновик, условно меняет тег через `--force-with-lease`, загружает пять файлов и скачивает их для сверки сумм. Обновляет описание, возвращает публичный статус тому же выпуску и проверяет скачивание и адрес.

Неизменяемый выпуск, изменившиеся refs, метаданные или набор файлов останавливают подготовку. Опубликованные коммиты main и теги 0.0.1-0.0.3 сохраняются.

Замена реализована в [replace_release.py](../dev/release/replace_release.py). Без `--apply` скрипт только готовит и проверяет локальную копию. Фаза записи требует эту копию. Нужны Python 3.11+, Git и авторизованный GitHub CLI.

## Восстановление

GitHub CLI [удаляет прежний файл перед загрузкой замены](https://cli.github.com/manual/gh_release_upload). При сбое скрипт восстанавливает сохранённый тег, пять файлов, заголовок и описание. Перед возвратом публичного статуса скачанные файлы должны совпасть по суммам. Идентификаторы файлов и счётчики скачиваний при замене могут измениться.

Отменённая задача или принудительно завершённый процесс не выполнят автоматический откат. Скачайте recovery artifact и запустите `replace_release.py` с прежними параметрами и `--restore` вместо `--apply`: скрипт импортирует bundle старого тега и проверит скачанные восстановленные файлы.

Если автоматический откат не удался, изучите `rollback-error.json` и recovery artifact. Сохраняйте выпуск черновиком до восстановления согласованных файлов и refs. Постороннее изменение удалённых refs останавливает автоматический откат, чтобы не затереть обновление. Повтор с новыми ожидаемыми значениями допустим только после разбора причины.

Сохраните recovery artifact в локальном архиве автора до истечения 90 дней хранения в Actions. После успеха проверьте оба README, ссылки, требования runtime, исходники тега и суммы скачанных файлов. Согласованные About/topics и поддержку примените отдельно.
