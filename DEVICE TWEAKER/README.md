**DEVICE TWEAKER** - низкоуровневая утилита для Windows 10 и Windows 11, предназначенная для оптимизации аппаратных прерываний (MSI / MSI-X), точной привязки очередей устройств к ядрам процессора (CPU Affinity) и прямого управления регистрами модерации USB-контроллеров (xHCI IMOD).

Утилита заменяет собой устаревший стек разрозненных инструментов (**MSI Utility v3**, **Microsoft Interrupt Affinity Policy Tool**, **GoInterruptPolicy**, а также вызовы **RWEverything** и самодельные скрипты записи IMOD, блокируемые современными античитами). Все задачи объединены в едином приложении с автоматическим определением топологии процессора, кастомным подписанным драйвером ядра и возможностью мгновенного отката к исходному заводскому состоянию системы.

## Архитектура и возможности

### 1. Векторные прерывания MSI / MSI-X (Message Signaled Interrupts)
- **Устранение конфликтов разделяемых линий IRQ:** Перевод устройств из устаревшего режима физических линий (Line-based / INTx) в векторный режим MSI / MSI-X. Каждому устройству и очереди назначается собственный вектор прерывания, а доставка сигнала выполняется прямой записью (PCIe Memory Write) в адресное пространство Local APIC целевого ядра процессора без опроса чужих драйверов.
- **Включение режима MSI / MSI-X:** Запись параметра `MSISupported = 1` в реестре устройства (`Device Parameters\Interrupt Management\MessageSignaledInterruptProperties`).
- **Снятие ограничения на количество векторов (MessageNumberLimit = 0):** Удаление искусственного ограничения операционной системы. При значении `0` (режим Unlocked) параметр `MessageNumberLimit` удаляется из реестра, что позволяет шинному драйверу `pci.sys` выделить полный пул векторов, запрошенный контроллером в таблице MSI-X (до 2048 векторов по спецификации PCI-SIG).
- **Приоритет диспетчеризации прерываний:** Установка параметра `DevicePriority = 3` (`High`) в ветке `Affinity Policy` для первоочередного обслуживания очередей мыши и видеокарты на уровне ядра Windows.

### 2. Распределение очередей прерываний по ядрам (CPU Affinity)
- **Точечная маршрутизация:** Назначение целевых логических процессоров через системный параметр `DevicePolicy = 4` (`IrqPolicySpecifiedProcessors`) и битовую маску `AssignmentSetOverride` (с поддержкой до 64 логических процессоров).
- **Интеллектуальный алгоритм авто-оптимизации (AUTO):**
  - **AMD Ryzen (Dual-CCD / 3D V-Cache):** Прерывания видеокарты и мыши закрепляются за физическими ядрами чиплета CCD0 с быстрым кэшем L3. Исключаются задержки межчиплетной шины Infinity Fabric (~20 нс внутри CCD против 70-90 нс между чиплетами через I/O Die).
  - **Intel Core (Hybrid):** Очереди периферии и видеокарты направляются строго на производительные P-ядра. Энергоэффективные E-ядра и соседние потоки Hyper-Threading исключаются из очередей реального времени.
  - **Изоляция мыши и сетевого стека:** Мышь изолируется на физическом ядре с наивысшим аппаратным рейтингом CPPC2, а сетевой адаптер выносится на отдельное ядро во избежание пересечения системных вызовов DPC.
  - **Рейтинги ядер CPPC2:** Чтение журнала событий Windows ETW (Event ID 55 провайдера `Microsoft-Windows-Kernel-Processor-Power`, параметр `MaximumPerformancePercent`) обеспечивает мгновенное определение лучших физических ядер процессора без задержек.

### 3. Системное резервирование ядер (ReservedCpuSets)
- **Изоляция ядер на уровне планировщика Windows:** Конфигурация системного параметра `[HKLM\System\CurrentControlSet\Control\Session Manager\kernel] ReservedCpuSets`.
- **Принцип работы:** Битовая маска исключает выбранные процессоры из пула ядер общего назначения. Системный планировщик перестает распределять на эти ядра фоновые системные службы и непривязанные DPC, сохраняя процессорные циклы для игровых потоков и прерываний реального времени.

### 4. Аппаратная модерация USB xHCI IMOD (драйвер DTIMOD.sys)
- **Регистры интерраптеров xHCI:** Согласно спецификации Intel xHCI (раздел 5.5.2), каждый аппаратный интерраптер контроллера имеет 32-битный регистр `IMOD` с шагом таймера 250 наносекунд.
- **Устранение стандартной задержки Windows:** Стандартный драйвер `USBXHCI.SYS` часто выставляет интервал модерации 50 мкс (`0xC8`) или 1 мс (`0xFA0`), удерживая пакеты в буфере. Отключение модерации (`IMOD = 0`) снимает искусственную задержку, передавая прерывание на шину PCIe немедленно по завершении транзакции.
- **Безопасный кастомный драйвер ядра (Ring 0):** Собственный подписанный драйвер `DTIMOD.sys` активируется строго по требованию для отображения физической памяти MMIO через `MmMapIoSpace`. Не требует отключения защиты `VulnerableDriverBlocklist` в Windows 11 и полностью совместим со всеми античитами (Vanguard, EAC, BattlEye).
- **Физическая топология контроллеров:** Программа различает прямой процессорный контроллер (CHIP 0 / Direct CPU Root Complex) и чипсетные хабы (CHIP 1), позволяя изолировать мышь на процессорном порту с нулевой задержкой, а звук вывести на чипсет с интервалом 1 мс для защиты аудиопотока.

### 5. Сетевая оптимизация (NIC ITR и RSS)
- **Аппаратная модерация сетевых карт (ITR / EITR / IntrMit):** Прямое считывание и отключение таймеров модерации сетевых адаптеров Intel (I210, I211, I225, I226, I350, I219) и Realtek (RTL8111, RTL8125, RTL8126).
- **Масштабирование на стороне приема (RSS):** Настройка параметров `*NumRssQueues` и `*RssBaseProcNumber` в ветке адаптера. Ограничение очередей RSS и их вынос с системного ядра CPU 0 предотвращают конкуренцию сетевого стека с игровым процессом.
- **Отключение Energy Efficient Ethernet (EEE):** Предотвращение перехода сетевого контроллера в энергосберегающие состояния физического трансивера (PHY) во время простоя линии.

### 6. Ограничение фонового ввода (Windows 11 RawMouseThrottleDuration)
- **Управление параметром RawMouseThrottleDuration:** Настройка системного параметра в ветке `HKCU\Control Panel\Mouse` (доступен в Windows 11 начиная со сборки 22621.1928 / KB5028185).
- **Снижение фоновой нагрузки:** Ограничение частоты опроса сырого ввода мыши для неактивных фоновых окон (диапазон от 1 до 20 мс) устраняет паразитный опрос процессора мышками 1000-8000 Гц в фоновых приложениях без влияния на активное игровое окно.

### 7. Резервное копирование и защита заводского состояния
- **Неизменяемый исходный снимок системы:** Автоматическое сохранение чистого снимка настроек Windows при первом запуске утилиты с защитой от перезаписи.
- **Дифференциальные контрольные точки:** Сохранение состояния перед каждым нажатием APPLY.
- **Восстановление в один клик:** Возможность пошагового отката любого шага или полного возврата к заводским настройкам Windows.

## Варианты поставки

- **Поддерживаемые ОС:** Windows 10 и Windows 11 (64-bit, сборки 19041 и новее).
- **Исполняемые файлы:**
  - `DEVICE.TWEAKER.exe` (~4 МБ) - компактный исполняемый файл, требует установленного [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0).
  - `DEVICE.TWEAKER.SelfContained.exe` (~150 МБ) - полностью автономная сборка с интегрированной средой выполнения .NET 8, готовая к запуску на чистых системах без сторонних зависимостей.

## Методология верификации результатов

Для объективной проверки влияния настроек прерываний и модерации рекомендуется использовать инструментальные средства телеметрии Windows:

1. **Анализ активности ISR и DPC по ядрам (ETW / Windows Performance Recorder):**
   ```cmd
   wpr -start CPU.light -start GPU.light
   :: Тестовая сессия в игре (1-2 минуты)
   wpr -stop trace.etl
   ```
   Открытие полученного файла `trace.etl` в **Windows Performance Analyzer (WPA)** позволяет наглядно оценить распределение DPC/ISR по логическим ядрам (график *DPC/ISR Duration by Module and Function*) и убедиться в отсутствии DPC-пиков на игровых ядрах.

2. **Мониторинг стабильности времени кадра:**
   Использование **CapFrameX** или **PresentMon** для замера распределения времени кадра (p95, p99, p99.9) и процента статтеров до и после применения настроек.

3. **Проверка интервалов опроса USB:**
   Утилита **MouseTester** позволяет визуализировать интервалы опроса (Plot: *Interval vs Time*) и убедиться в устранении пакетной буферизации при отключении модерации xHCI IMOD.

## Сборка из исходного кода

Для сборки требуется установленный [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

Сборка обеих версий приложения с формированием релизного пакета и контрольных сумм SHA-256 выполняется командой:

```powershell
powershell -ExecutionPolicy Bypass -File ".\publish-variants.ps1" -Flavor both
```

Скомпилированные файлы и манифест `SHA256SUMS.txt` размещаются в папке:
```
.\bin\ReleasePackages\v0.0.4-alpha.2\
```
