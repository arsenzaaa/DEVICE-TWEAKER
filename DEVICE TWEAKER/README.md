**DEVICE TWEAKER** - низкоуровневая утилита для Windows 10 и Windows 11, предназначенная для тонкой настройки векторных аппаратных прерываний (MSI / MSI-X), жесткой привязки очередей к ядрам процессора (CPU Affinity), прямого управления аппаратными регистрами модерации USB-контроллеров (xHCI IMOD) через кастомный драйвер ядра и оптимизации сетевого стека (RSS / NIC ITR).

По умолчанию планировщик ядра Windows и слой HAL нацелены на усредненную пропускную способность (throughput) и энергоэффективность. При высоких частотах опроса периферии (1000-8000 Гц) стандартные политики распределения прерываний и очередей DPC концентрируют нагрузку на системном ядре CPU 0 или направляют очереди ввода мыши, видеокарты и сетевого адаптера на одни и те же физические ядра. Это приводит к аппаратной конкуренции за исполнительные конвейеры процессора, межъядерным задержкам синхронизации кэша L1/L2/L3, вытеснению критических игровых потоков и микростаттерам времени кадра (frametime jitter).

DEVICE TWEAKER заменяет собой стек разрозненных устаревших решений, таких как **MSI Utility v2 / v3**, **Microsoft Interrupt Affinity Policy Tool (intaffinity)**, **GoInterruptPolicy**, а также утилиту **RWEverything** и самодельные скрипты записи IMOD, которые блокируются современными античитами (Vanguard, Easy Anti-Cheat, BattlEye) из-за требования отключать VulnerableDriverBlocklist. Все эти задачи, включая настройку очередей RSS, аппаратную модерацию сетевых адаптеров, системную изоляцию ядер через ReservedCpuSets и контроль фонового ввода Windows 11, объединены в едином приложении с автоматическим определением аппаратной топологии и гарантией безопасного отката (ORIGINAL STATE).

## Архитектура и ключевые возможности

### 1. Векторные прерывания MSI / MSI-X (Message Signaled Interrupts)
- **Устранение конфликтов разделяемых прерываний (IRQ Sharing):** В устаревшем режиме Line-based (INTx) несколько физических устройств делят общий номер IRQ. При поступлении сигнала операционная система вынуждена последовательно опрашивать подпрограммы обслуживания (ISR) всех подключенных устройств на приоритете DIRQL. Векторный режим MSI / MSI-X назначает каждому устройству и каждой аппаратной очереди собственный уникальный вектор прерывания, а доставка сигнала осуществляется прямой записью сообщения (PCIe Memory Write) в адресное пространство Local APIC целевого ядра.
- **Включение режима MSI / MSI-X:** Запись параметра `MSISupported = 1` в реестре устройства (`Device Parameters\Interrupt Management\MessageSignaledInterruptProperties`).
- **Снятие ограничения на количество векторов MSI (MessageNumberLimit):** В реестре Windows параметр `MessageNumberLimit` задает максимальное число векторов MSI, разрешенных драйверу шины `pci.sys`. В DEVICE TWEAKER выбор значения `0` (режим Unlocked) физически удаляет параметр `MessageNumberLimit` из ветки реестра устройства, снимая искусственный лимит операционной системы. Это позволяет шинному драйверу выделить полный пул векторов, запрошенный контроллером в аппаратной таблице MSI-X (до 2048 векторов согласно спецификации PCI-SIG PCIe / MSI-X).
- **Приоритет диспетчеризации прерываний (DevicePriority):** Установка параметра `DevicePriority = 3` (`High`) в подразделе `Device Parameters\Interrupt Management\Affinity Policy` для первоочередного обслуживания очередей мыши и видеокарты на уровне HAL и ядра Windows.

### 2. Распределение очередей прерываний по ядрам (CPU Affinity)
- **Точечная маршрутизация:** Назначение целевых логических процессоров через системный параметр `DevicePolicy = 4` (`IrqPolicySpecifiedProcessors`) и битовую маску `AssignmentSetOverride` (с поддержкой конфигураций до 64 логических процессоров).
- **Интеллектуальный алгоритм автоматической оптимизации (AUTO):**
  - **Мышь и контроллер ввода:** Выделение отдельного изолированного физического ядра с наименьшей латентностью для обработки прерываний USB-контроллера мыши без конкуренции с фоновыми системными задачами.
  - **Видеокарта (GPU):** Закрепление графических очередей за физическими ядрами основного чиплета (CCD0 на процессорах AMD Ryzen). На процессорах с асимметричным 3D V-Cache (Ryzen 9 7900X3D / 7950X3D) это гарантирует обработку графического стека на ядрах с увеличенным кэшем L3. На стандартных двухчиплетных процессорах (Ryzen 9 5900X, 5950X, 7900X, 7950X, 9900X, 9950X) локализация очередей на CCD0 изолирует поток рендеринга от задержек межчиплетной шины Infinity Fabric (внутри одного чиплета задержка составляет ~20 нс, тогда как межчиплетный обмен через I/O Die занимает 70-90 нс).
  - **Сетевые адаптеры и клавиатура:** Вывод сетевых очередей и контроллера клавиатуры на независимые ядра, исключая прерывание потоков рендеринга игры и обработки мыши.
  - **Гибридные процессоры Intel:** Назначение высокоскоростных устройств строго на производительные P-ядра. Энергоэффективные E-ядра исключаются из обработки прерываний реального времени из-за пониженной частоты, узких конвейеров и повышенных задержек.
  - **Исключение соседних потоков Hyper-Threading / SMT:** Исключение соседних логических потоков (sibling threads) на ядрах, занятых критическими задачами, предотвращает аппаратную конкуренцию за конвейеры выполнения (ALU, AGU, FPU) и вытеснение кэш-памяти L1/L2.
  - **Учет аппаратного рейтинга ядер по спецификации ACPI CPPC v2:** Чтение данных инициализации процессора (ETW Event ID 55 провайдера `Microsoft-Windows-Kernel-Processor-Power`, параметр `MaximumPerformancePercent`) позволяет алгоритму AUTO идентифицировать наиболее производительные физические ядра процессора (AMD Preferred Cores / Intel Turbo Boost Max 3.0) для приоритетного размещения критических очередей.

### 3. Системное резервирование ядер (ReservedCpuSets)
- **Изоляция ядер на уровне планировщика Windows:** Конфигурация системного параметра `[HKLM\System\CurrentControlSet\Control\Session Manager\kernel] ReservedCpuSets`.
- **Принцип изоляции:** Битовая маска исключает выбранные процессоры из пула ядер общего назначения. Системный планировщик операционной системы перестает распределять на эти ядра фоновые системные службы, непривязанные процессы пользовательского режима и системные DPC общего назначения (ntoskrnl, symcryptk, tcpip). В сочетании с прямой маршрутизацией прерываний (`AssignmentSetOverride`) это обеспечивает выделенные ядра для игровых потоков и прерываний периферии реального времени.

### 4. Аппаратная модерация прерываний xHCI IMOD (кастомный драйвер DTIMOD.sys)
- **Физический конвейер обработки ввода:**
  `Сенсор мыши -> Контроллер мыши -> USB-пакет (125 мкс при 8000 Гц) -> xHCI Port -> Transfer Ring TRB -> Transfer Event -> Interrupter -> Event Ring -> Таймер IMOD (задержка N * 250 нс) -> Запись MSI-X в PCIe -> Local APIC ядра -> DIRQL (ISR драйвера мыши) -> Постановка KDPC в очередь -> Выполнение DPC -> Поток Windows Raw Input -> Игровой движок -> Кадр GPU`.
- **Регистры интерраптеров xHCI:** Согласно спецификации Intel xHCI (раздел 5.5.2), каждый аппаратный интерраптер контроллера имеет 32-битный регистр `IMOD` (Interrupt Moderation Register). Шаг таймера зафиксирован аппаратно и равен 250 наносекундам.
- **Проблема стандартной модерации Windows:** Стандартный драйвер `USBXHCI.SYS` по умолчанию часто выставляет интервал модерации 50 мкс (значение `0xC8` / 200) либо 1 мс (значение `0xFA0` / 4000). Контроллер xHCI удерживает прерывание в Event Ring до истечения таймера, что приводит к пакетной доставке данных и джиттеру задержки опроса. Отключение модерации (`IMOD = 0`) устраняет искусственную задержку на уровне хост-контроллера, передавая прерывание на шину PCIe немедленно по завершении транзакции.
- **Безопасный кастомный драйвер ядра Ring 0:** В отличие от небезопасных утилит (RWEverything), требующих выключения защиты VulnerableDriverBlocklist и вызывающих блокировки в соревновательных играх античитами (Vanguard, EAC, BattlEye), DEVICE TWEAKER использует собственный подписанный драйвер `DTIMOD.sys`. Драйвер загружается строго по требованию, отображает диапазон физической памяти MMIO через `MmMapIoSpace` и напрямую считывает и записывает значения в регистры интерраптеров.
- **Индивидуальная настройка интерраптеров:** Нулевая задержка модерации (`0x0`, 0 нс) для мыши и клавиатуры обеспечивает немедленную передачу каждого прерывания в процессор. Для USB-аудиокарт и ЦАП возможность выставления интервала 1 мс (`0xFA0`) снижает частоту прерываний без щелчков и разрывов звукового буфера.
- **Разведение периферии по физической топологии:** Программа определяет физический путь контроллеров: прямой процессорный контроллер (CHIP 0 / Direct CPU Root Complex) и чипсетные хабы (CHIP 1 / CHIP 1+), что позволяет изолировать мышь на процессорном контроллере, а звук и клавиатуру вывести на чипсет.

### 5. Сетевая оптимизация (NIC ITR и RSS)
- **Аппаратная модерация сетевого адаптера (ITR / EITR / IntrMit):** Прямое считывание и отключение регистров модерации прерываний сетевых карт семейств Intel (I210, I211, I225, I226, I350, I219) и Realtek (RTL8111, RTL8125, RTL8126), снижая сетевой джиттер и задержку доставки пакетов в стек NDIS.
- **Компромисс модерации прерываний (ITR Trade-off):** Отключение модерации прерываний минимизирует задержку обработки входящих пакетов, что оптимально для соревновательных игр с относительно небольшим объемом сетевого трафика (~200-500 пакетов/с). При высокой нагрузке (скачивание файлов, стриминг на полной скорости канала) отключение ITR приводит к росту числа прерываний до миллионов в секунду, повышая нагрузку на процессор.
- **Масштабирование на стороне приема (Receive Side Scaling):** Конфигурация параметров `*NumRssQueues` и `*RssBaseProcNumber` в ключе сетевого адаптера (`HKLM\...\Class\{4d36e972-e325-11ce-bfc1-08002be10318}`). Для соревновательного гейминга оптимально ограничение числа очередей RSS (до 1-2) с выносом обработки входящих очередей с системного ядра CPU 0 на выделенное ядро, предотвращая конкуренцию с игровым процессом.
- **Отключение Energy Efficient Ethernet (EEE):** Предотвращение перехода сетевого контроллера в энергосберегающие состояния физического уровня PHY во время простоя линии.

### 6. Ограничение фонового ввода (Windows 11 RawMouseThrottleDuration)
- **Системный параметр подсистемы ввода:** Настройка параметра `RawMouseThrottleDuration` в ветке `HKCU\Control Panel\Mouse` (доступен в Windows 11 начиная со сборки 22621.1928 / KB5028185).
- **Снижение фоновой нагрузки:** Позволяет ограничить частоту опроса сырого ввода мыши для неактивных фоновых окон (диапазон от 1 до 20 мс, где значение 20 соответствует 50 Гц). Это устраняет избыточную нагрузку на процессор от мышей с опросом 1000-8000 Гц при работе фоновых приложений без снижения частоты опроса в активной игре.

### 7. Управление питанием шинных интерфейсов
- **Отключение USB Selective Suspend:** Запрет перевода USB-портов в режим выборочного энергосбережения (`SelectiveSuspendEnabled = 0`), предотвращая задержки при выходе устройства из сна.
- **Политики энергопотребления:** Отключение энергосберегающих состояний сетевых карт и шинных контроллеров PCIe.

### 8. Система резервного копирования и отката (ORIGINAL STATE)
- **Неизменяемый заводской профиль:** При первом запуске создается снимок исходного состояния Windows до внесения каких-либо твиков.
- **Дифференциальные точки восстановления:** Автоматическое сохранение контрольных снимков перед каждым применением настроек (кнопка APPLY).
- **Восстановление в один клик:** Возможность пошагового отката изменений либо полного сброса параметров операционной системы к оригинальным заводским значениям.

## Универсальная совместимость

DEVICE TWEAKER разработан на базе низкоуровневых стандартов шины PCI Express, спецификации xHCI и ядра Windows NT, обеспечивая универсальную поддержку современного оборудования:

- **Любые процессоры x64:** Полная совместимость со всеми семействами процессоров AMD (Ryzen, Threadripper, EPYC, включая одночиплетные и двухчиплетные модели с 3D V-Cache) и Intel (Core 10-14 поколений, Core Ultra, Xeon, гибридные конфигурации P/E-ядер и монолитные кристаллы).
- **Любые устройства PCI Express:** Видеокарты всех производителей (NVIDIA GeForce / RTX, AMD Radeon, Intel Arc), твердотельные накопители NVMe M.2 и SATA AHCI контроллеры, карты захвата, звуковые интерфейсы.
- **Любые USB-контроллеры xHCI:** Стандартные хост-контроллеры USB 3.0 / 3.1 / 3.2 / USB4 процессорных комплексов и десктопных чипсетов AMD, Intel, а также дискретные чипы ASMedia, VIA, Renesas.
- **Любые сетевые адаптеры:** Ethernet и Wi-Fi адаптеры с поддержкой драйверов NDIS 6.x, протоколов MSI-X и RSS (со встроенным прямым доступом к регистрам модерации ITR/EITR/IntrMit для контроллеров Intel и Realtek).

## Безопасность и драйвер ядра DTIMOD.sys

- **Штатное сканирование в Ring 3:** Обычный запуск утилиты, чтение дерева устройств и нажатие кнопки **ОБНОВИТЬ (REFRESH)** выполняются исключительно через стандартные интерфейсы Windows SetupAPI и системный реестр без загрузки кода в ядро.
- **Загрузка драйвера по требованию:** Кастомный драйвер `DTIMOD.sys` активируется только при запросе чтения регистров интерраптеров или записи значений IMOD для выполнения физического отображения памяти через `MmMapIoSpace`.
- **Защита от сбоев (BSOD):** Драйвер сохраняется в системной памяти до планового перезапуска Windows во избежание сбоев ядра, характерных для динамической выгрузки драйверов шинных устройств.
- **Применение системных политик:** Модификации политик прерываний Windows (`DevicePolicy`, `DevicePriority`, `MessageSignaledInterruptProperties`, `ReservedCpuSets`) вступают в силу после плановой перезагрузки ПК при инициализации таблиц APIC слоем HAL.

## Варианты поставки

- **Операционная система:** Windows 10 или Windows 11 (64-bit, сборки 19041 и новее).
- **Исполняемые файлы:**
  - `DEVICE.TWEAKER.exe` (~4 МБ) - компактный исполняемый файл, требует установленного [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0).
  - `DEVICE.TWEAKER.SelfContained.exe` (~150 МБ) - полностью автономная сборка с интегрированной средой выполнения .NET 8, готовая к запуску на чистых системах без сторонних зависимостей.

## Методология верификации результатов

Для объективной проверки влияния настроек прерываний и модерации рекомендуется использовать инструментальные средства телеметрии Windows:

1. **Анализ активности ISR и DPC по ядрам (ETW / Windows Performance Recorder):**
   ```cmd
   wpr -start CPU.light -start GPU.light
   :: Выполните тестовую игровую сессию (1-2 минуты)
   wpr -stop trace.etl
   ```
   Открытие полученного файла `trace.etl` в **Windows Performance Analyzer (WPA)** позволяет наглядно оценить распределение DPC/ISR по логическим ядрам (график *DPC/ISR Duration by Module and Function*), убедиться в отсутствии DPC-пиков на игровых ядрах и проверить корректность изоляции очередей.

2. **Мониторинг стабильности времени кадра (Frametime Pacing):**
   Использование **CapFrameX** или **PresentMon** для замера распределения времени кадра (p95, p99, p99.9) и среднеквадратичного отклонения времени рендеринга (Stuttering Percentage / Frametime Variance) до и после применения профиля.

3. **Проверка частоты опроса и джиттера USB (MouseTester):**
   Утилита **MouseTester** позволяет визуализировать интервалы опроса (Plot: *Interval vs Time*) и убедиться в устранении пакетной буферизации (batching) при отключении модерации xHCI IMOD.
