## <samp>[ ИЗМЕНЕНИЯ 0.0.4 ]</samp>

Обновление после 0.0.3.

<table width="100%">
<tr><th align="left" width="860"><strong>Режимы прерываний</strong></th></tr>
<tr><td width="860">

<ul>
<li>Добавлен IRQ Mode. Настройка MSI Mode из реестра, текущий режим прерываний и поддерживаемые устройством режимы в HW показаны отдельно.</li>
<li>При открытии программы режим определяется по выделенным ресурсам Windows или через уже загруженный DTIMOD.sys. Открытие и обычное обновление списка не загружают драйвер. Если данных для различения MSI / MSI-X недостаточно, это указано в интерфейсе.</li>
<li>Добавлена общая кнопка <strong>СЧИТАТЬ IRQ</strong> для всех PCI-устройств из списка. Она уточняет режим по MSI / MSI-X Enable через DTIMOD.sys и загружает драйвер, если он ещё не загружен.</li>
<li>Чтение IRQ Mode выполняется в фоне. После обновления списка результаты предыдущего запроса отбрасываются.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>IMOD и NIC ITR</strong></th></tr>
<tr><td width="860">

<ul>
<li><strong>ПРОВЕРИТЬ</strong> в блоке IMOD раскрывает считанные значения и таблицу. Для просмотра результата больше не нужно включать галочку применения IMOD.</li>
<li>Фоновое чтение IMOD больше не подготавливает и не заменяет файл драйвера. Используется уже загруженный DTIMOD.sys.</li>
<li>Автозапуск IMOD / NIC ITR переведён в Планировщик заданий: задача <code>\DEVICE TWEAKER\IMOD</code> работает от SYSTEM и применяет настройки при входе в Windows, после выхода из сна и при подключении USB/HID-устройства. Раньше автозапуск срабатывал только при входе в Windows.</li>
<li>Файлы автозапуска лежат в <code>%ProgramData%\DEVICE TWEAKER\Startup</code>, изменять их могут только администраторы и SYSTEM. Скрипт <code>ApplyIMOD.ps1</code> остаётся открытым и работает без EXE; значения хранятся в <code>profile.json</code>, перед запуском сверяются SHA-256 runtime, драйвера и загрузчика, журналы хранятся 14 дней. Прежний автозапуск из AppData и ключа Run переносится автоматически.</li>
<li>Программа и автозапуск используют один код записи регистров и чтения карты interrupter'ов. Исправлено расхождение: автозапуск брал interrupter устройства из Slot Context, а не из TRB его кольца передачи, и после перезагрузки мог раскладывать роли иначе, чем показывала программа.</li>
<li>Рядом с текущими значениями IMOD показано время чтения; после подключения или отключения устройства карта помечается «устройства изменились».</li>
<li><strong>СОХРАНИТЬ</strong> для NIC ITR выключает в реестре собственную адаптивную модерацию драйвера (<code>*InterruptModeration</code>, у Intel также <code>ITR</code>), которая иначе перезаписывала значение регистра. <strong>УДАЛИТЬ</strong> возвращает значение драйвера. Состояние видно в строке Interrupt Moderation.</li>
<li>Программа и автозапуск больше не загружают DTIMOD.sys одновременно.</li>
<li>Бекапы сохраняют профиль автозапуска; бекапы со старым скриптом при восстановлении переводятся в новый формат без потери значений.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>Бекапы и восстановление</strong></th></tr>
<tr><td width="860">

<ul>
<li>Исправлено восстановление USB Selective Suspend из бекапа: вместо прямой записи в реестр используется Windows Power API. Питание от сети и батареи восстанавливается отдельно, в план питания из бекапа.</li>
<li>Параметры плана питания проверяются повторным чтением после восстановления; текущий план не переключается.</li>
<li>В диалогах бекапов имя файла отделено от сообщения. Полный путь можно открыть и скопировать, папку с бекапами можно открыть отдельной кнопкой.</li>
<li>Удаление бекапа больше не закрывает меню восстановления и не открывает отдельное окно с результатом.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>Энергосбережение</strong></th></tr>
<tr><td width="860">

<ul>
<li>Добавлено повторное чтение энергосбережения из WMI после записи. Неподдерживаемая функция, ошибки запроса / записи и несовпадение значений выводятся отдельно.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>Отображение устройств</strong></th></tr>
<tr><td width="860">

<ul>
<li>Исправлен Polling Rate мыши: после подтверждённого замера Raw Input в интерфейсе показывается измеренная частота, даже если она ниже максимума USB endpoint. У клавиатуры низкая активность нажатий не подменяет частоту устройства.</li>
<li>Убраны повторяющиеся подписи polling. USB-роли выводятся в порядке: мышь, клавиатура, геймпад, микрофон, аудио, камера.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>RSS</strong></th></tr>
<tr><td width="860">

<ul>
<li>Диагностика RSS различает неподдерживаемую функцию, отсутствие данных, ошибку чтения, ошибку применения и пропуск настройки. Совпадение сохранённых и активных параметров отмечается только после подтверждённого чтения.</li>
<li>Убраны необоснованные предупреждения для Wi-Fi и адаптеров, у которых CPU для RSS выбирает Windows. Настройки Wi-Fi по-прежнему пропускаются. Увеличено время ожидания запроса активного RSS.</li>
<li>Исправлен выбор CPU для RSS: процессоры берутся по одному на физическое ядро, SMT-соседи пропускаются, вместе с базовым CPU записываются <code>*MaxRssProcessors</code> и <code>*RssMaxProcNumber</code>.</li>
<li>Число очередей RSS ограничено значениями, которые предлагает драйвер, и числом векторов MSI-X.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>Интерфейс / навигация</strong></th></tr>
<tr><td width="860">

<ul>
<li>Переработаны диалоги результатов, подтверждений, выбора папки бекапа и проверки системы. Основное сообщение отделено от технических подробностей.</li>
<li>Исправлены обрезка текста в полях, переносы в диалогах и компоновка блоков. Уточнены подписи текущих и сохранённых значений.</li>
<li>Доработаны выпадающие списки и навигация с клавиатуры. Home / End / Page Up / Page Down и Ctrl+Z в поле ввода обрабатываются самим полем.</li>
<li>Убрана белая вспышка блоков при чтении IRQ Mode. Исправлен порядок освобождения ресурсов при закрытии окна.</li>
<li>Обновлены формулировки RU/EN, подписи причин создания бекапов и индикатор изменённых настроек. Исправлено переключение языка у динамических строк и Power Saving.</li>
<li>Обновлены цвета категорий устройств: GPU и сеть легче различать.</li>
<li>Кнопки фильтров на русском больше не теряют пробелы после смены языка («[ ВСЕ ]» вместо «[ВСЕ]»).</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>Диагностика</strong></th></tr>
<tr><td width="860">

<ul>
<li>Добавлен идентификатор сборки приложения при сохранении номера 0.0.4. По логу можно различить разные EXE одной версии.</li>
<li>В логи добавлены источник и время чтения IRQ Mode, длительность запросов RSS и подробные статусы чтения / применения.</li>
<li>Добавлена проверка системы перед настройкой USB IMOD: состояние Blocklist / HVCI / Microsoft Defender и служб FACEIT / Vanguard.</li>
<li>Ошибки чтения реестра, WMI и топологии USB записываются в лог как предупреждения, а не пропускаются молча. Числа, даты и значения регистров в логах форматируются одинаково при любой локали Windows.</li>
</ul>

</td></tr>
</table>

<table width="100%">
<tr><th align="left" width="860"><strong>Разработка и проверки</strong></th></tr>
<tr><td width="860">

<ul>
<li>Из MainForm вынесены планировщик CPU, запись MSI / affinity, восстановление, NIC ITR и polling. Существующие правила распределения CPU сохранены.</li>
<li>Проверки и тест-панель перенесены в dev/qa. Панель входит только в отдельную разработческую сборку, обычный EXE её не содержит.</li>
<li>Расширен стенд разработки: воспроизводимые сценарии, снимки GUI и переходов, RU/EN, модели масштабирования, тестовые файлы и сравнение кадров. Автономный прогон работает на невидимом рабочем столе без применения настроек Windows.</li>
<li>Добавлены проверки чувствительности тестов к намеренным поломкам и сверка исходников / готовых компонентов по SHA-256. Обновлены документация сборки, описание программы и скриншоты.</li>
<li>DTIMOD.sys записывает только в память, которую Windows выделила указанному PCI-устройству; прежняя общая запись в физическую память удалена. Проверка диапазона выполняется на модели драйвера вместе с намеренной поломкой.</li>
</ul>

</td></tr>
